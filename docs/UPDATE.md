# Обновление уже работающей копии CashWatch

## Обновление интеграции 17 октября после пакета Plus 2

Подготовлены два разных patch с разными базами:

- `CashWatch_Update_Team_Integration.patch` — для последнего полного пользовательского ZIP с SHA-256 `a57d313180a97794ac4ff8cf1ed10344d4599de5ddafe37f8060102631af317f`. В нём уже должен работать ручной журнал и runtime contract.
- `CashWatch_GitHub_Integration.patch` — для GitHub `main` на `14a9e507455abb446062243518321a692d488bef`. Он нужен владельцу Git-копии для переноса общего результата.

Их нельзя применять друг за другом или менять местами. Оба приводят свою указанную базу к одному общему исходному дереву. Пакет `CashWatch_Integrated_20261017.zip` содержит это дерево без истории Git, данных, весов, ключей и локальных отчётов. Самостоятельная установка зависимостей для уже работающего Mac не нужна.

В корне работающей пользовательской копии, после скачивания первого patch:

```bash
ls -l "$HOME/Downloads/CashWatch_Update_Team_Integration.patch"
git apply --check "$HOME/Downloads/CashWatch_Update_Team_Integration.patch"
```

При отсутствии ошибки:

```bash
git apply "$HOME/Downloads/CashWatch_Update_Team_Integration.patch"
```

Если `ls` не нашёл файл, сначала сохраните скачанный patch в Downloads под указанным именем. Если `git apply --check` сообщает несовпадение, применение не выполняйте: рабочая копия отличается от базы, нужен точный diff. Ни `--reject`, ни `reset --hard` для этого не используются. Для нового отдельного каталога можно распаковать общий ZIP и сравнить изменения, сохраняя `.env`, модели и локальные данные в исходной копии.

В patch нет `.env`, моделей, банковских данных или журналов. После обновления перезапустите уже работающий uvicorn и откройте страницу заново. Перед перезагрузкой страницы скачайте локальный журнал: записи хранятся в памяти браузера. Ключ интерфейса после перезагрузки вводится заново; серверный `.env` обновлением не меняется.

Текущие результаты: [GITHUB_INTEGRATION.md](GITHUB_INTEGRATION.md). Передача Plus 1: [PLUS1_HANDOFF.md](PLUS1_HANDOFF.md). Передача и QA Plus 2: [UI_QA.md](UI_QA.md), [DEMO_SCRIPT.md](DEMO_SCRIPT.md), [DELIVERY_CHECKLIST.md](DELIVERY_CHECKLIST.md). Разделы ниже описывают предыдущий patch runtime/journal и сохраняются как история, а не как требование применить его повторно.


Обновление от 17 октября 2026 года добавляет локальный журнал ручного просмотра, общий runtime contract и проверку `jury_check.py --expect-benchmark`. API результата жюри сохранён. Новых Python-зависимостей нет; повторная установка venv или скачивание весов для этих изменений не нужны.

## Вариант для последнего выданного архива

Файл `CashWatch_Update_Runtime_Journal.patch` применяется из корня существующего `forte-datathon` с помощью установленного Git. Он подготовлен для предыдущего исходного ZIP с SHA256 `a988d04ef5abe7146257009d5d5da23990838215a7b7c5db95b0b6ded72125a0`. Git-репозиторий для применения обычного patch не требуется. Изменяются только исходники, тесты, документация и их `SOURCE_MANIFEST.sha256`. `.env`, `.venv`, данные, runtime и модели не входят в patch.

Сначала завершите текущий запрос, если он выполняется, и остановите Uvicorn **Ctrl+C**. Перед перезагрузкой страницы скачайте несохранённые локальные заметки, если они есть. Сохраните текущие незакоммиченные правки своим обычным способом; patch не предназначен для переписывания независимой версии участника команды.

Скачайте patch в Downloads. В терминале, где открыт корень вашего проекта, проверьте применимость:

```bash
git apply --check "$HOME/Downloads/CashWatch_Update_Runtime_Journal.patch"
```

При успехе команда завершается без ошибки. Только затем примените:

```bash
git apply "$HOME/Downloads/CashWatch_Update_Runtime_Journal.patch"
```

При ошибке `patch does not apply`, другом имени скачанного файла или уже установленном обновлении не добавляйте `--reject`, не стирайте файлы и не применяйте patch принудительно. Сохраните сообщение и передайте Pro 1; можно сравнить свою копию с новым полным ZIP в отдельной папке. Чужой изменённый код не заменяется вслепую.

Откройте прежнее окружение и запустите приложение:

```bash
source .venv/bin/activate
python -m uvicorn cashwatch.main:app_factory --factory --host 127.0.0.1 --port 8000 --workers 1
```

На Mac обновите страницу **Cmd+Shift+R**, введите прежний локальный ключ, если он нужен для API. После выбора видео под плеером появится **«Журнал ручного просмотра»**. Он работает и до авторизации модели. При отсутствии весов или допущенных правил анализ остаётся недоступным — это ожидаемое состояние.

## Передача на другую машину

Участникам, которые ещё не начинали работу с предыдущим пакетом, передайте новый полный `CashWatch_ForteBank_Datathon.zip` и соответствующий файл из `docs/prompts/`. Уже работающие участники применяют тот же patch либо передают Pro 1 конфликтующие изменения для объединения. Виртуальное окружение Mac не копируется в Windows/WSL; инструкции для этой машины находятся в `RTX_4050.md`.

Если сменились исходники Python, прежний benchmark больше не является точным reference нового runtime. После фиксации кода/модели/правил/параметров выполните новый успешный `--mode jury` benchmark, перезапустите сервис и передайте его путь в `jury_check.py --expect-benchmark`. Сравнение фиксирует заявленную конфигурацию, а проверка реальных весов, устройства, качества и времени полного HTTP-запроса остаётся отдельной.
