# Развёртывание на сервере команды

У второго Pro есть ноутбук с RTX 4050; первый CUDA-прогон выполняется по [RTX_4050.md](RTX_4050.md). Для него предусмотрен Linux/WSL2 без обязательного Docker. Приведённая ниже схема контейнеров остаётся отдельным вариантом серверного размещения. Нативный Windows-supervisor не поддерживается; публичная доступность ноутбука ещё не настроена.

## Что подготовлено

`Dockerfile`, `compose.yaml`, `compose.gpu.yaml` и `deploy/nginx.conf` описывают запуск Python API и отдельного nginx. Рабочий контейнер модели находится во внутренней сети `inference`, имеет доступ к локальным весам только для чтения и запускается от непривилегированного пользователя. HTTP-порт API не опубликован на хосте. Gateway публикует только `127.0.0.1:8080`.

В этой среде Docker отсутствовал. Конфигурация прочитана, но образ, GPU, доступность порта и запрет исходящей сети контейнера не проверены фактическим запуском. Это обязательные оставшиеся действия на сервере, а не пройденная приёмка.

## Локальная проверка сборки

Нужны локально подготовленные веса `models/Qwen3-VL-2B-Instruct`, `.env` с приватным ключом и проверенные включённые правила. Этап скачивания зависимостей/весов завершается до обработки банковских видео.

```bash
docker compose config --quiet
docker compose build
docker compose up -d
docker compose ps
```

Для Linux-сервера с уже настроенным NVIDIA Container Toolkit и подходящим GPU:

```bash
docker compose -f compose.yaml -f compose.gpu.yaml up --build -d
```

Этот override не предоставляет GPU и не устанавливает драйвер. Не используйте его на MacBook Air. Для Mac тестируйте нативный Python/MPS по [MAC_M4.md](MAC_M4.md) и отдельно измеряйте память и время. Для Runpod Pods, где Compose не поддерживается, подготовлен [CLOUD_GPU_RUNBOOK.md](CLOUD_GPU_RUNBOOK.md).

## Доказательство локальности

Проверьте маршруты сети рабочего контейнера и отсутствие доступа к внешнему HTTPS при сохранённой доступности gateway. Затем при запрещённой исходящей сети выполните `check_model --smoke` и анализ разрешённого локального validation-видео. Успешный ответ, полученный при запрете egress, — необходимое свидетельство работы без Hub/API; одного наличия `HF_HUB_OFFLINE` недостаточно.

На Linux worker перед импортом ML-библиотек дополнительно включает процессный фильтр libseccomp: создание IPv4/IPv6-сокетов запрещено, унаследованные интернет-сокеты не допускаются, Unix IPC остаётся доступным. Если фильтр или его проверка не работают, обработка завершается `network_isolation_unavailable`. Проверка `python -m cashwatch.network_guard --check` применяется к дочернему процессу и не отключает сеть API или shell. Это узкий фильтр доверенного ML-процесса; он не заменяет сетевой namespace и не защищает от всех способов связи через чужой Unix proxy. На macOS этот механизм явно не применяется.

Код инференса использует `local_files_only=True`, `trust_remote_code=False` и safetensors. FFmpeg/FFprobe принимают протоколы `file,pipe`. В интерфейсе нет внешних библиотек и CDN; CSP ограничивает соединения своим origin. Downloader моделей — отдельный инструмент подготовки. `jury_check.py` посылает видео только на явно указанный собственный сервер команды; не направляйте его на чужой endpoint.

Обычный HTTP nginx внутри Compose не является облачным AI API, но TLS на внешней границе всё равно нужен для передачи ключа и видео. Не устанавливайте внешний сервис аналитики, error tracking с содержимым запросов или облачную обработку медиа.

## Публичный адрес

Определите существующий сервер и домен команды. Настройте на нём HTTPS-терминацию с проксированием на `127.0.0.1:8080`. Конкретный домен, сертификат и публичный IP не выбраны, поэтому их конфигурация не выдумана в этом пакете.

Прокси должен пропускать тело не менее 100 МиБ, не буферизовать целиком входное видео перед API, поддерживать таймауты полного запроса и не журналировать API-ключ/тело. Текущий внутренний nginx использует `proxy_request_buffering off`; внешний прокси нужно проверить отдельно.

С другой сети проверьте главную страницу и весь путь `POST → polling → done/failed`. Проверка `/healthz` подтверждает только HTTP-процесс. Не считайте сервер готовым по зелёному healthcheck без реального анализа.

## Финальная приёмка

Зафиксируйте commit исходников, SHA весов, конфигурацию модели, prompt, реестр правил и зависимости. Сначала выполните validation-прогон через `jury_check.py`; после окончания настройки — один независимый holdout-прогон. В отчёте должны быть все видео, включая failed и отсутствующие ответы, а также полный wall-clock каждого запроса.

Проверьте самый длинный ролик, холодный старт, несколько последовательных загрузок, неверный ключ, неподдерживаемый и повреждённый файл, поведение при параллельной загрузке и перезапуске. Таймаут 275 секунд — механизм остановки, а не результат бенчмарка.

Передать организаторам нужно реально работающие URL интерфейса/API и приватный ключ согласованным каналом. Не публикуйте ключ, банковские видео, кадры или описания в GitHub. Передача сообщений и доступов организаторам в рамках этой разработки не выполнялась.

## Завершение работы

`docker compose down` останавливает сервисы и сохраняет именованный том с результатами. Удаление тома уничтожает сохранённые результаты: выполняйте его только после проверки необходимости сохранения и требований организаторов. Серверный TTL не удаляет скачанные пользователем отчёты, исходный учебный архив или файлы в его локальном каталоге экспериментов.
