# Подготовка данных и независимая оценка

Скрипты используют стандартную библиотеку Python. Для подготовки метаданных нужен локальный `ffprobe`. Они не обучают модель, не подбирают пороги, не обращаются к LLM или внешним сервисам. `prepare_dataset.py` не извлекает кадры; `evaluate.py` не открывает исходные видео и не показывает изображения.

Перед использованием реальных источников для настройки и перед независимой
оценкой сверить исходный журнал обучающей экспозиции и провести соответствующий
[локальный review применимости и групп](LOCAL_RULE_REVIEW.md). Подготовка
метаданных и синтетические технические проверки могут выполняться раньше.
`scripts/prepare_review.py` готовит отдельные приватные таблицы; он не преобразует
журнал UI в эталонные метки и не разрешает оценку автоматически.

Реальные видео кейса при разработке этих инструментов не использовались. Автоматические проверки выполняются на синтетических манифестах, ответах, байтах файлов и одном искусственно созданном коротком видео.

## 1. Манифест без разметки

Из корня проекта, в активированном Python-окружении:

```bash
python scripts/prepare_dataset.py \
  --input-dir /absolute/path/to/open \
  --out data/manifest.local.json
```

Входная папка просматривается рекурсивно. Поддерживаются `.mov` и `.mp4` без учета регистра расширения. Пустая папка и файл без читаемых параметров видеопотока дают явную ошибку. Символическая ссылка на видео за пределами входной папки отклоняется. При вызове `ffprobe` разрешены только протоколы `file,pipe`, чтобы файл, похожий на видео, не инициировал сетевую загрузку.

Без CSV у **каждого** видео остаются:

```json
{
  "label": null,
  "events": [],
  "group_id": "unassigned",
  "camera_id": "unassigned",
  "split": "unassigned"
}
```

Имя файла, видимые действия и порядок файлов не превращаются в метку. Автоматического случайного распределения по разделам нет.

### Пути и идентификаторы

`metadata.input_dir` содержит абсолютный путь к входной папке. И `video_id`, и `path` — один и тот же POSIX-путь **относительно этой папки**, например `camera_a/clip_01.mov`.

Корректное разрешение пути:

```python
from pathlib import Path

video_path = Path(manifest["metadata"]["input_dir"]) / video["path"]
```

Путь не отсчитывается от папки, где лежит JSON-манифест. Перемещение или переименование входных файлов требует повторной подготовки манифеста и согласования `video_id` в предсказаниях. Результаты API сопоставляются по `video_id`; `job_id` сам по себе не является идентификатором исходного файла в этом манифесте.

### Метаданные

Для каждого видео сохраняются SHA-256 всех байтов файла, длительность, FPS и размер видеопотока. Длительность берется сначала из первого видеопотока, затем из `duration_ts × time_base`, затем из контейнера. FPS — `avg_frame_rate` с резервом `r_frame_rate`. Размер — кодированные ширина и высота, без применения метаданных поворота.

Средний FPS у видео с переменной частотой кадров не задает точную временную сетку. Изменение размера, времени модификации или inode файла во время подготовки останавливает создание манифеста. Параметры `--ffprobe` и `--probe-timeout` позволяют указать исполняемый файл и время ожидания одного файла; по умолчанию это `ffprobe` и 30 секунд.

## 2. Разметка CSV

Обязательные колонки: **`video,label`**. Необязательные: `timecode_sec,rule_id,group_id,camera_id,split`.

Формат — UTF-8, допускается BOM, разделитель — запятая. В `video` используется относительный POSIX-путь с `/`. Для файла из вложенной папки одного basename недостаточно. Абсолютные пути, `..`, обратные слеши и неизвестные файлы отклоняются.

Ниже только пример структуры. Имена, метки, таймкоды и `r1`/`r2` вымышлены и не являются разметкой видео кейса:

```csv
video,label,timecode_sec,rule_id,group_id,camera_id,split
camera_a/clip_01.mov,1,12.4,r1,staging_01,camera_a,train
camera_a/clip_01.mov,1,27.1,r2,staging_01,camera_a,train
camera_b/clip_02.mp4,0,,,staging_02,camera_b,validation
camera_c/clip_03.mov,1,35.2,r1,staging_03,camera_c,holdout
```

Подготовка:

```bash
python scripts/prepare_dataset.py \
  --input-dir /absolute/path/to/open \
  --labels /absolute/path/to/labels.csv \
  --out data/manifest.local.json
```

Правила чтения CSV:

- `label` — только `0` или `1`. `1.0`, текстовые названия классов и пустая метка в существующей строке отклоняются.
- Видео без строки CSV остается с `label=null`; отсутствие строки не означает норму.
- Несколько строк на видео объединяются в список событий. Метки и все непустые повторные значения `group_id`, `camera_id`, `split` должны согласовываться. Пустые необязательные поля не стирают ранее указанное значение.
- Заглушки неизвестной группы/камеры (`unassigned`, `unknown`, `none`, `null`, `n/a`) обрабатываются как отсутствие значения; в выходе неизвестное значение всегда `unassigned`.
- У `label=0` не может быть ни таймкода события, ни `rule_id` события.
- У `label=1` допускается отсутствие событий: это разметка только на уровне видео. Она не включается в оценку локализации событий.
- `rule_id` без `timecode_sec` — ошибка. Таймкод без `rule_id` допустим; он пригоден для оценки времени, но не известного типа.
- Таймкоды отсчитываются в секундах от начала видео и должны быть конечными числами в пределах `0 ≤ t ≤ duration_sec`.
- Повтор одинаковой пары `(timecode_sec, rule_id)` на одном видео считается дубликатом разметки и отклоняется. Разные события могут иметь один таймкод, если их `rule_id` различаются.
- Допустимы `train`, `validation`, `holdout`, `unassigned`. Неизвестные названия, конфликт разделов и опечатки в заголовках колонок дают ошибку.

В метаданные манифеста также попадает хеш CSV. Выход записывается атомарно. Скрипт не позволяет перезаписать выходом исходное видео или CSV.

## 3. Защита от утечки между разделами

Разделы должны назначаться по независимым группам исходных сцен. Фрагменты одного исходника, его перекодировки, зависимые дубли и синхронные ракурсы одной постановочной сцены следует относить к одной группе. Что считать независимой группой, команда фиксирует после изучения материалов организаторов.

Проверяются все `train`, `validation` и `holdout` в манифесте, даже если команда оценивает только один из разделов:

- одинаковый SHA-256 в разных разделах — ошибка;
- одинаковый известный `group_id` в разных разделах — ошибка;
- один путь в разных разделах — ошибка;
- повтор `video_id` в манифесте — ошибка.

Одинаковые байты под разными именами в одном разделе показываются в диагностике `duplicate_hashes`. Скрипт не удаляет записи автоматически. Такие дубликаты могут давать отдельной сцене лишний вес в метрике.

Подготовка позволяет оставить неизвестную группу. **Оценка не разрешена**, если у хотя бы одного видео в любом назначенном разделе неизвестен `group_id`. Значение `unassigned`, пустое значение и смысловые заглушки вроде `unknown` не доказывают независимость. Неназначенные файлы с `split=unassigned` не используются в оценке.

Проверка не устанавливает, правильно ли человек заполнил группы: уникальное имя группы на каждое видео не делает связанные видео независимыми. `camera_id` сохраняется для анализа распределения, но совпадение камеры само по себе не объявляется утечкой. Проверка исходников по содержимому, поиск похожих сцен и независимость по камерам этим скриптом не выполняются.

`evaluate.py` не читает журнал обучающей экспозиции и не проверяет, использовали ли
эти источники ранее для обучения, настройки prompt или правил. Согласование
групп и сверка экспозиции выполняются отдельно по локальной инструкции выше;
успешная проверка заявленных полей не подтверждает независимость оценки.

## 4. Входные предсказания

Принимается JSON-список ответов или объект с полем `predictions`:

```json
{
  "predictions": [
    {
      "video_id": "camera_c/clip_03.mov",
      "status": "done",
      "verdict": "violation",
      "violations": [
        {
          "type": "Точное название из утвержденного реестра",
          "rule_id": "r1",
          "timecode_sec": 35.2,
          "evidence_frames": [
            {
              "timestamp_sec": 35.2,
              "image_base64": "ЗДЕСЬ_ДОЛЖЕН_БЫТЬ_НАСТОЯЩИЙ_BASE64_JPEG"
            }
          ]
        }
      ],
      "elapsed_sec": 42.7
    }
  ]
}
```

Это пример полей, а не готовый валидный ответ: строка изображения — видимая заглушка, которая проверку не пройдет. `rule_id` в предсказании необязателен. Внешний API может сохранять свой точный формат, а локальный экспортер результатов добавляет `video_id`, `elapsed_sec` и, при наличии, проверенный `rule_id` для оценки.

Завершенным считается только `status="done"`. Допустимые вердикты: `violation` и `no_violation`. Непустой список `violations` должен согласовываться с первым; пустой — со вторым.

Отсутствующий ответ, `failed`, все еще `processing`, неизвестный статус, несовместимый вердикт или некорректные доказательства становятся отдельным **failed**. Они не превращаются в `no_violation`. Дубликаты предсказаний, неизвестные `video_id` и ответы из другого, не запрошенного раздела считаются ошибкой всего входного файла. Лишние ответы не игнорируются молча. Повторные JSON-ключи, NaN и Infinity отклоняются.

`elapsed_sec` необязателен. Его отсутствие или `null` означает неизвестную задержку, а не ноль. Указанное отрицательное, нечисловое или бесконечное значение считается ошибкой ответа.

## 5. Запуск оценки

```bash
python scripts/evaluate.py \
  --manifest data/manifest.local.json \
  --predictions data/predictions.validation.local.json \
  --split validation \
  --rules config/rules.json \
  --out data/evaluation.validation.local.json
```

Финальный прогон после фиксации модели, правил и параметров:

```bash
python scripts/evaluate.py \
  --manifest data/manifest.local.json \
  --predictions data/predictions.holdout.local.json \
  --split holdout \
  --rules config/rules.json \
  --out data/evaluation.holdout.local.json
```

`--split train` не поддерживается. Скрипт не запускает обучение, дообучение, настройку порогов или подбор лучшего прогона. Дисциплина использования holdout остается процессным требованием: повторно настраивать систему по его результатам нельзя считать независимой финальной проверкой.

`--rules` передается явно. Если реестр задан, `type` должен в точности совпадать с его `title`; при наличии `rule_id` они также должны согласовываться. Без `rule_id` разрешено только точное однозначное сопоставление по `title`. Дубликаты ID или неоднозначные одинаковые названия в реестре отклоняются. Известные `rule_id` разметки должны присутствовать в переданном реестре.

Если `--rules` не передан, текст `type` не преобразуется в ID по сходству или смыслу. Для метрик типов используются только явные `rule_id` предсказаний. Заголовок, похожий на название категории, не подтверждает соответствие.

Проверка реестра в оценщике нужна для точного сопоставления имен, а не для запуска правил: он не включает отключенные правила и не анализирует видео заново.

## 6. Метрики

### На уровне видео

Положительный класс — видео с нарушением по предоставленной разметке (`label=1`). В `confusion_matrix` сохраняются `tp`, `tn`, `fp`, `fn` **для корректно завершенных ответов**. Число сбоев и причины стоят отдельно.

Формулы:

- `precision = TP / (TP + FP)`;
- `recall = TP / (TP + FN)`;
- `f1 = 2TP / (2TP + FP + FN)`;
- `completed_video_accuracy = (TP + TN) / число завершенных ответов`;
- **`effective_video_accuracy = (TP + TN) / число всех видео запрошенного раздела`**.

При нулевом знаменателе значение равно JSON `null`. Итоговая точность считает каждый сбой ошибкой. Дополнительно сохраняются покрытие ответами и сквозные доли найденных положительных / правильно обработанных отрицательных видео: их знаменатели включают сбои. Это не позволяет скрыть отказ на сложных примерах за хорошей точностью оставшихся ответов.

### События и время

При допусках **1, 2 и 5 секунд** вычисляется диагностическое сопоставление событий один к одному, отдельно внутри каждого видео. Используется максимальное по количеству пар двудольное сопоставление: один сигнал не закрывает несколько истинных событий. Граница допуска включена. Кандидаты упорядочены по близости времени; глобальный минимум суммарной временной ошибки не заявляется.

Эти показатели **не объявляются официальной метрикой организаторов**. Результаты без типа оценивают только временную локализацию. Положительные видео без event-разметки исключаются целиком из этой части отчета. Отрицательные видео включаются, чтобы считать ложные события.

Список истинных событий у включенных видео предполагается исчерпывающим. Если разметка покрывает только несколько замеченных событий, метрика ложных срабатываний не имеет надежной интерпретации — сначала нужно завершить разметку. Сбой на положительном видео с event-разметкой дает ноль предсказанных событий и соответствующие FN. Сбой на отрицательном видео не может породить событийный FN, поэтому число сбоев и итоговая точность видео обязательны рядом с этой метрикой.

### Типы событий

Типы оцениваются только при известных ID истинных событий. Видео со смесью известных и неизвестных типов исключается целиком из оценки типов, чтобы сигнал на неизвестное истинное событие не превратился в ложный FP известного класса. Положительные видео без таймкодов уже исключены из событийной оценки.

Для известных типов требуется и временное совпадение, и точный ID. Неразрешенный тип предсказания остается несовпавшим сигналом в агрегате; отдельный выдуманный класс ему не назначается. Если нет ни одного пригодного истинного события с известным типом, раздел показывает `available=false`, без искусственно рассчитанного результата.

## 7. Целостность доказательств

У каждого предсказанного нарушения проверяется:

1. От одного до трех кадров.
2. Корректный строгий base64 без data-URI-префикса.
3. JPEG-конверт: начало `FF D8 FF`, завершение `FF D9`.
4. Конечные, неотрицательные таймкоды в пределах длительности видео.
5. Строго возрастающий порядок кадров без повторения таймкодов.
6. Хотя бы один кадр рядом с `timecode_sec` нарушения: по умолчанию расстояние не больше `1 / fps`. Другие кадры могут показывать «до» и «после».

Для точного совпадения опорного таймкода:

```bash
python scripts/evaluate.py \
  --manifest data/manifest.local.json \
  --predictions data/predictions.holdout.local.json \
  --split holdout \
  --evidence-time-tolerance-sec 0 \
  --out data/evaluation.holdout.local.json
```

Можно задать другой неотрицательный допуск. Это параметр технической проверки, не правило НБРК и не официальный допуск жюри.

**JPEG не декодируется.** Маркеры и base64 не доказывают, что файл полностью декодируем, что изображение показывает заявленное действие, что оно извлечено из нужного видео или что таймкод не был подменен. Скрипт проверяет взаимную согласованность переданных полей, а не происхождение изображения. Для проверки происхождения нужно отдельно сверять доказательства с локальным декодером и исходным файлом; средний FPS также не доказывает точные PTS для VFR.

В итоговый JSON не копируются base64, содержимое кадров и текстовые описания кадров/действий из предсказания. Сохраняются счетчики, причины ошибок, идентификаторы видео, временные метрики и хеши входных JSON-файлов. Исходные видео при оценке не перечитываются для повторного вычисления SHA-256; оценка использует заявленные значения подготовленного манифеста.

## 8. Задержка

`p50_sec` и `p95_sec` рассчитываются только по известным `elapsed_sec`, линейной интерполяцией в позиции `(n−1) × p`. Это заявленная задержка прогона, а не измерение оценщиком времени модели.

Условие времени проверяется до округления: `elapsed_sec <= 300`. Значение 300 проходит, 300.00001 не проходит. Показаны отдельно:

- число известных и неизвестных/некорректных задержек;
- число ответов в пределах / сверх 300 секунд;
- доля в пределах среди известных задержек и среди всех видео;
- число и доля **успешно завершенных** ответов в пределах 300 секунд.

Быстрый сбой не считается успешным ответом в пределах лимита. Неизвестная задержка не подменяется средним, нулем или временем запуска оценщика.

## 9. Проверки инструментов

```bash
python -m pytest tests/test_dataset_tools.py -q
```

Проверяются реальные границы риска: конфликт разметки, временные границы, несколько событий на видео, повтор хешей и групп, запрет оценки при неизвестной независимости, отказы сервиса, взаимно однозначное сопоставление, отсутствие угадывания типов, поврежденные доказательства, граница 300 секунд и безопасная запись выходного файла. Интеграционный тест `ffprobe` использует искусственно сгенерированное черное видео; он пропускается, если отсутствует FFmpeg или ffprobe.

Файлы реальных манифестов, предсказаний, отчетов и видео должны оставаться локальными. Команды используют суффикс `.local.json` для удобства исключения из Git; сам суффикс не является механизмом ограничения доступа или публикации.
