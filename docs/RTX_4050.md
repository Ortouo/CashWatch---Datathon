Платный GPU остаётся резервным вариантом, если имеющееся оборудование не проходит измерение или не обеспечивает доступность сервиса. Аренда не выполнена, бюджет ещё не подтверждён.

Пользователь сообщил о работающем базовом API/UI на Mac. Состояние WSL, CUDA и настоящей генерации на этом ноутбуке пока остаётся неизвестным; не повторяйте уже успешно выполненные шаги, продолжайте с первого неподтверждённого этапа. Промпт следующего этапа: [02_PRO_ML.md](prompts/02_PRO_ML.md).

## 1. Что означает RTX 4050 для нашего проекта

По [официальной таблице NVIDIA](https://www.nvidia.com/en-us/geforce/laptops/40-series/) RTX 4050 Laptop имеет **6 GB GDDR6**. Это паспортный объём выделенной видеопамяти; фактические название GPU и доступный объём проверяются командой `nvidia-smi`. [Microsoft объясняет](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/), что shared GPU memory берётся из системной RAM. Она не увеличивает физическую VRAM с 6 до 14 или 22 ГБ.

Qwen3-VL-2B — кандидат для первого запуска. Грубая оценка для 2 млрд параметров по 2 байта — около 4 ГБ только на параметры. Реальные размеры checkpoint, vision-компоненты, промежуточные тензоры, контекст, кеш и нагрузка рабочего стола требуют дополнительной памяти. Наличие 6 ГБ **не подтверждает**, что наш полный путь поместится. Скорость этого ноутбука не измерена, а маленькая CUDA-операция не является замером Qwen.

Замороженный DINOv2 и обучение небольшого классификатора уже доступны в проекте. Функциональный эксперимент на четырёх видео состоялся на Linux CPU; его не требуется повторять для первого запуска API. Дальнейшее обучение должно соблюдать журнал использованных SHA и разбиение сценариев из `FUNCTIONAL_TRAINING.md`.

### Два бюджета памяти на Windows с 16 ГБ

| Ресурс | Что учитываем перед запуском |
|---|---|
| Системная RAM ноутбука | 16 ГБ по сообщению пользователя; её используют Windows, WSL и другие приложения. |
| Память Linux внутри WSL2 | [Лимит по умолчанию — 50% RAM Windows](https://learn.microsoft.com/en-us/windows/wsl/wsl-config), то есть примерно 8 ГБ на этом ноутбуке. Это лимит VM, а не обещание 8 ГБ свободной памяти процессу. Существующие настройки могут задавать другое значение. Проверять `free -h` внутри Ubuntu. |
| Выделенная память RTX 4050 Laptop | 6 ГБ по спецификации NVIDIA; доступный остаток проверять отдельно через `nvidia-smi`. |

Наш адаптер сначала загружает Qwen в память CPU, затем переносит всю модель на CUDA. Поэтому памяти должно хватать на обоих этапах. Для первого прогона оставьте текущие настройки WSL, завершите свои лишние игры и ML-задачи, сократите фоновую нагрузку Windows и запускайте один worker. Docker Desktop для этого пути не требуется. Одновременный DINO-тренинг на той же GPU отложите до завершения замера.

Не назначайте WSL все 16 ГБ и не заменяйте существующий `.wslconfig` готовым шаблоном. Если возникнет нехватка памяти, сначала установите, исчерпана RAM Linux или VRAM CUDA. Swap использует диск: он не увеличивает VRAM и может ухудшить время анализа. Изменение глобальных лимитов WSL имеет смысл после такой диагностики; оно затрагивает и другие WSL2-дистрибутивы. Команда `wsl --shutdown`, применяемая для перезапуска настроек, завершает работающие WSL-окружения — в обычный первый запуск её не включаем.

## 2. Выбрать правильное окружение

| Установленная система | Путь запуска CashWatch |
|---|---|
| Linux с доступной NVIDIA GPU | Нативный Linux, отдельный Python venv, CUDA wheels PyTorch. |
| Windows с уже работающим WSL2 | Окружение Ubuntu/Linux внутри WSL2. Установка и команды ниже выполняются в его Bash. |
| Windows без готового WSL2 | Сначала получить диагностику и настроить WSL2 по инструкции Microsoft. Наличие RTX не означает, что WSL уже установлен. |
| Нативный Windows Python / PowerShell | Не использовать для полного benchmark текущего проекта: надёжная остановка дерева процессов реализована через POSIX. Preflight выдаёт `unsupported_native_windows_supervisor`; benchmark отказывается до чтения входного видео. |

Для подтверждённого Windows-ноутбука выбираем **Ubuntu внутри WSL2 + CUDA**. Microsoft документирует [CUDA внутри WSL2](https://learn.microsoft.com/en-us/windows/ai/directml/gpu-cuda-in-wsl). Это поддержка платформы, а не результат тестирования CashWatch в WSL. Техническая диагностика этого ноутбука ещё не выполнена.

### Первичная диагностика Windows — PowerShell

Эти команды только читают технические сведения:

```powershell
Get-ComputerInfo -Property OsName,OsVersion,OsBuildNumber,OsArchitecture,CsTotalPhysicalMemory | Format-List
wsl --list --verbose
nvidia-smi --query-gpu="name,memory.total,memory.free,driver_version" --format=csv
```

Версия дистрибутива в выводе WSL должна быть **2**. При отсутствии команды или GPU зафиксируйте сообщение; не объявляйте диагностику успешной. Если уже есть подходящая Ubuntu с `VERSION 2`, откройте её и переходите к разделу 3. При `VERSION 1` нужен переход на WSL2 по [инструкции Microsoft](https://learn.microsoft.com/en-us/windows/wsl/basic-commands), а не запуск GPU-команд в прежнем окружении. Столбец CUDA Version в обычном `nvidia-smi` описывает возможности драйвера, а версия runtime установленных wheels проверяется через `torch.version.cuda`.

Если WSL отсутствует и выбран этот путь, [официальная инструкция Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install) описывает установку. В PowerShell администратора можно сначала посмотреть доступные дистрибутивы, затем выбрать Ubuntu 24.04, если он есть в списке:

```powershell
wsl --list --online
wsl --install -d Ubuntu-24.04
```

Следуйте сообщениям установки; может потребоваться перезагрузка и первое создание Linux-пользователя. Не удаляйте существующие дистрибутивы и не переустанавливайте рабочее окружение только ради этих команд. При уже настроенном подходящем Linux/WSL используйте его.

**Драйвер для WSL устанавливается в Windows.** NVIDIA прямо указывает [не ставить Linux display driver внутри WSL](https://docs.nvidia.com/cuda/wsl-user-guide/index.html). Для обычного Linux нужен его Linux-драйвер; ограничение относится именно к WSL. Отдельный CUDA Toolkit для готовых PyTorch wheels в этом пути не требуется; он нужен при сборке CUDA-кода/расширений из исходников, которую мы здесь не добавляем. [Разъяснение PyTorch](https://discuss.pytorch.org/t/should-i-install-the-extra-cudatoolkit-and-cudnn/194528/2).

## 3. Установка в Ubuntu 24.04 / WSL2

Следующие команды — **Bash внутри Linux**, не PowerShell. Для другого дистрибутива нужно адаптировать только установку системных пакетов. Microsoft [рекомендует хранить проект в Linux-файловой системе](https://learn.microsoft.com/en-us/windows/wsl/filesystems), когда инструменты запускаются из Linux: используем каталог внутри `/home`, чтобы не добавлять обмен через `/mnt/c` в измерение загрузки весов. Python venv с Mac или нативного Windows сюда не переносится. При ошибке остановитесь на конкретном шаге и сохраните техническое сообщение.

```bash
sudo apt-get update
sudo apt-get install -y python3.12 python3.12-venv ffmpeg libseccomp2 unzip
```

Для новой установки создайте папку приёма архива и откройте её в Проводнике:

```bash
mkdir -p ~/cashwatch-inbox
cd ~/cashwatch-inbox
explorer.exe .
```

Скопируйте в открывшееся окно скачанный `CashWatch_ForteBank_Datathon.zip`. Затем в той же Ubuntu распакуйте его в новый каталог; это сохраняет любые предыдущие рабочие копии:

```bash
cashwatch_run_dir="$(mktemp -d "$HOME/cashwatch-run-XXXXXX")"
unzip CashWatch_ForteBank_Datathon.zip -d "$cashwatch_run_dir"
cd "$cashwatch_run_dir/forte-datathon"
```

Если проект уже установлен или вы работаете в существующей согласованной Git-ветке, используйте эту рабочую копию. Следующий блок выполняется из её корня, где находятся `pyproject.toml` и `README.md`:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-core.lock.txt
python -m pip install torch==2.8.0 torchvision==0.23.0 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -e '.[ml,test,training]'
python -m pip check
python scripts/init_env.py
```

Официальная [таблица PyTorch 2.8.0](https://pytorch.org/get-started/previous-versions/) содержит пару Torch 2.8.0 / torchvision 0.23.0 для CUDA 12.8 на Linux и Windows. Наша модель использует Transformers 4.57.1, Accelerate 1.10.1 и huggingface-hub 0.35.3, закреплённые в `pyproject.toml`. Установка wheels не заменяет совместимый драйвер. Не обновляйте всё окружение между сравниваемыми экспериментами.

Проверьте CUDA и Linux-ресурсы:

```bash
nvidia-smi --query-gpu=name,memory.total,memory.free,driver_version --format=csv
free -h
df -h .
python -c "import torch; ok=torch.cuda.is_available(); print({'torch':torch.__version__,'cuda_runtime':torch.version.cuda,'cuda_available':ok}); print({'gpu':torch.cuda.get_device_name(0),'vram_bytes':torch.cuda.get_device_properties(0).total_memory,'probe':torch.ones(1,device='cuda').sum().item()}) if ok else None"
```

Если `nvidia-smi` в WSL не найден, проверьте документированный путь `/usr/lib/wsl/lib/nvidia-smi` с теми же аргументами. Некоторые поля WSL могут возвращать `N/A`; не подставляйте вместо них предположения. В `free -h` отдельно смотрите `total` и `available`: первый показывает видимый Linux объём, второй — текущую доступную память. `df -h .` проверяет свободное место для окружения, весов и отчётов.

## 4. Публичные веса и локальная обработка

Банковские видео, кадры и описания сцен не передаются облачным GPT, Claude или другим AI API. Они обрабатываются локальным кодом на ноутбуке команды. Скачивание публичных весов — отдельный этап с интернетом:

```bash
env -u HF_HUB_OFFLINE -u TRANSFORMERS_OFFLINE -u HF_DATASETS_OFFLINE \
  python scripts/model_download.py --model qwen3-vl-2b --revision 89644892e4d85e24eaac8bacfd4f463576704203
python scripts/check_model.py --model-dir models/Qwen3-VL-2B-Instruct --verify-hashes

export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 HF_DATASETS_OFFLINE=1
export HF_HUB_DISABLE_TELEMETRY=1 DO_NOT_TRACK=1

python -m cashwatch.network_guard --check
python scripts/preflight.py --device cuda --out local_reports/preflight-rtx4050.json
```

Guard проверяется в одноразовом дочернем процессе. На Linux он должен запрещать обычное создание IPv4/IPv6-сокетов, сохраняя Unix IPC. Отказ `linux_inference_network_guard_unavailable` нельзя скрывать для зелёного отчёта: нужно проверить среду. Guard не заменяет проверку всей серверной сети и не должен обходиться выдачей модели сетевого Unix proxy.

При отсутствии активных правил `configuration_ready_for_jury=false` ожидаемо. Полный официальный текст и текущая редакция уже сверены; все три текущих правила ещё требуют проверки применимости и наблюдаемости в конкретных видео. `environment_ready_for_benchmark=true` проверяет окружение, но не гарантирует, что весь checkpoint поместится в GPU.

## 5. Начальный профиль с ограниченной памятью

В `scripts/benchmark_local.py` добавлен явный профиль **`rtx-4050`**:

| Параметр | Значение |
|---|---:|
| Устройство | Явно `cuda` |
| Частота выборки | 1 кадр/с |
| Окно / перекрытие | 6 с / 2 с |
| Максимум кадров в окне | 8 |
| Большая сторона JPEG | 384 px |
| Максимум выходных токенов | 768 |
| Максимальная длительность входа | 180 с |
| Одновременно анализируемые видео | 1 |

Профиль ограничивает число и размер изображений в одном вызове. Более короткое окно уменьшает временной контекст и увеличивает число вызовов на длинном видео; низкое разрешение может скрыть мелкие предметы. Поэтому профиль является **начальным вариантом для измерения**, а не доказанным улучшением скорости или качества. Запланированные окна всей записи не пропускаются; выборка 1 fps сама по себе не гарантирует обнаружения действий между кадрами.

CUDA dtype в существующем адаптере — BF16 при поддержке, иначе FP16. Вся модель переносится на GPU. Квантование, CPU offload и автоматическое переключение на CPU не включены. Если уже загрузка весов вызывает нехватку памяти, уменьшение окна не решает расход памяти самих параметров.

Подключите ноутбук к питанию, закройте другие локальные GPU/ML-задачи. Подставьте путь к разрешённому локальному видео из разработки, не из будущего holdout:

```bash
python scripts/benchmark_local.py \
  --video '/absolute/path/to/local/video.mov' \
  --device cuda \
  --profile rtx-4050 \
  --mode analyzer \
  --seconds 275 \
  --out local_reports/benchmark-rtx4050-first.json
```

`analyzer` позволяет проверить исполнение до утверждения правил, но не выдаёт юридический verdict. При пустом реестре входной prompt отличается от финального. После проверки правил нужен `--mode jury` с тем же `--rules config/rules.json`, который будет использовать API. Выполните короткий технический вход, затем самый длинный разрешённый validation-ролик; короткий успех не доказывает успешность длинного.

После принятия правил и фиксации кода сохраните reference для HTTP-проверки:

```bash
python scripts/benchmark_local.py \
  --video '/absolute/path/to/local/validation-video.mov' \
  --device cuda --profile rtx-4050 --mode jury \
  --rules config/rules.json --seconds 275 \
  --out local_reports/benchmark-rtx4050-jury.json
```

В отчёте теперь есть `runtime_contract`, `contract_stable` и фиксированные имена отличающихся полей. Изменение идентичности во время серии даёт код завершения `1`. Успех benchmark относится только к выбранному входу и среде; он ещё не включает HTTP и не является оценкой всех видео.

Запишите `status`, `analyzer_complete`, `wall_seconds`, `model_load_seconds`, `latency_budget_passed`, `supervisor_hard_stop`, числовые показатели памяти и число обработанных окон. Отчёты исключают кадры, base64 и тексты наблюдений. Их можно использовать для технического разбора, сохраняя банковские данные локально. Холодная загрузка модели входит в benchmark; HTTP-загрузка видео и передача результата ещё требуют отдельного замера через API.

## 6. Решение после первого замера

| Наблюдение | Следующее действие |
|---|---|
| CUDA недоступна | Проверить выбранное окружение, драйвер и wheels; не принимать CPU-выполнение за GPU-результат. |
| CUDA OOM / `memory_exhausted` при размещении на GPU | Зафиксировать свободную VRAM, освободить её от своих лишних процессов. Если модель всё равно не помещается, оценить другой checkpoint/backend отдельно или перейти к доступному устройству с большей VRAM. |
| Процесс завершён системой при загрузке без подтверждённого CUDA OOM | Проверить RAM внутри WSL и нагрузку Windows. Недостаток host RAM нельзя автоматически считать недостатком VRAM; сначала установить причину. |
| Нехватка памяти при анализе | Разобрать этап, размер входов и фактические показатели. Не уменьшать fps или обрезать видео ради успешного статуса. |
| Полный проход не уложился в 275 с | Сравнить измерения на том же validation-входе с M4/другим доступным GPU; зарезервировать время на HTTP. |
| Полный проход успешен | Проверить качество с утверждёнными правилами, длинный ролик, повторные последовательные задания и внешний API. |
| Распознавание работает, внешний адрес недоступен | Отдельно решить доставку запросов жюри. Локальный успех не подтверждает публичную доступность. |

Не запускать параллельно обучение DINO и Qwen-инференс на одной 6-ГБ GPU. Работу выполняют последовательными заданиями, сохраняя базовый commit и параметры. Макбук может параллельно проверять интерфейс и документацию без второй модели на RTX.

## 7. Настройки API после проверки правил

Для сопоставимого запуска сервера из того же Linux venv:

```bash
export CASHWATCH_DEVICE=cuda
export CASHWATCH_MAX_INFLIGHT=1
export CASHWATCH_TIMEOUT_SEC=275
export CASHWATCH_SAMPLE_FPS=1
export CASHWATCH_WINDOW_SEC=6
export CASHWATCH_OVERLAP_SEC=2
export CASHWATCH_MAX_FRAMES_PER_WINDOW=8
export CASHWATCH_MAX_NEW_TOKENS=768
export CASHWATCH_IMAGE_EDGE=384
export CASHWATCH_MAX_DURATION_SEC=180
export CASHWATCH_MAX_UPLOAD_MB=100
python -m uvicorn cashwatch.main:app_factory --factory --host 127.0.0.1 --port 8000 --workers 1
```

Во втором терминале того же Linux-окружения проверьте API с точным reference:

```bash
source .venv/bin/activate
python scripts/jury_check.py \
  --base-url http://127.0.0.1:8000 \
  --manifest data/manifest.local.json --split validation \
  --expect-benchmark local_reports/benchmark-rtx4050-jury.json \
  --out local_reports/predictions.validation.json
```

Перед первым POST проверяется успешный стабильный **jury** benchmark, полная идентичность и совпадение параметров, заявленной ревизии/хешей модели, правил и исходников. Analyzer-only reference не принимается. Проверка повторяется перед каждым следующим видео; при расхождении уже полученные ответы сохраняются, а отчёт остаётся неполным. Сообщение об ошибке содержит названия полей, без значений ключа и приватных путей. Без `--expect-benchmark` обычный smoke возможен, но совпадение с локальным измерением не подтверждено.

Хеши checkpoint в контракте **заявлены manifest**, а не перечитаны из многогигабайтных весов; фактическую целостность проверяет `check_model.py --verify-hashes`. Источники Python хешируются с диска: после изменения кода нужен перезапуск. Контракт не включает конкретную GPU, драйвер или версии PyTorch/CUDA. Сверьте их отдельно; перенос и полную HTTP-задержку нужно измерить на целевом сервере.

Нужны локальный `.env` с ключом, полные веса и включённые проверенные правила. Привязка к `127.0.0.1` даёт локальный адрес; это ещё не публичный URL. HTTPS, внешний маршрут, приём файла, опрос задания и доступность после дедлайна проверяются по `DEPLOYMENT.md`. Если сервис остаётся на ноутбуке, он должен сохранять питание, сеть и работу процесса во время судейства. Переход ноутбука в сон прерывает доступность.

Сначала качество оценивается на validation. После фиксации модели, параметров, prompt и правил выполняется заранее выбранный независимый holdout; все failed учитываются. До получения реальных результатов RTX 4050, M4 и облачный GPU остаются вариантами исполнения с неизвестной конкурсной производительностью.
