# Место запуска CashWatch до сдачи Datathon 26

**После уточнения пользователя первый GPU-прогон выполняем на ноутбуке участника Pro 2: Windows, 16 ГБ RAM, RTX 4050.** Для текущего проекта выбираем Ubuntu внутри WSL2, явное устройство CUDA и измерение полного времени обработки. Mac M4 с 16 ГБ используется параллельно для интеграции, просмотра и резервного MPS-прогона. Ни одно из этих устройств пока не доказало нужную скорость или доступность публичного URL. Платный собственный GPU-сервер остаётся резервом после измерений и подтверждения конкретного бюджета. Готовые облачные AI API для банковских видео текущий предоставленный кейс прямо запрещает.

Сообщение команды о возможности использовать облако учтено. При этом в доступных материалах нет нового текста организаторов, который отменяет ограничения конкретного кейса. Ниже отдельно показаны текст правил, наше прочтение и неизвестные сведения. Это решение по реализации, а не обещание допуска со стороны жюри.

Аренда вычислителя и покупка ответа модели — разные технические операции. API провайдера, который создает VM или управляет ею, не выполняет распознавание видео. При этом размещение своего API в той же учетной записи, из которой вызывается чужой VLM, не делает чужой inference локальным. Для оценки важно, какой процесс реально читает видео и где исполняются веса.

Собственный GPU VM не становится автоматически подходящим только потому, что у команды есть SSH. Нужно описать фактический путь данных. Если весь inference выполняется в worker команды, внешние AI-вызовы отсутствуют, а подготовленное приложение анализирует видео без исходящего интернета, это конкретное основание нашего прочтения § 7. Правила организаторов о передаче тестовых данных все равно действуют; соглашение с произвольным провайдером не известно по одному названию услуги.

Для этой работы не введен дополнительный обязательный этап переписки или согласования с организаторами. Неоднозначность прямо зафиксирована; подготовка кода, измерения на Mac и исследование доступной инфраструктуры могут продолжаться. Новое проверяемое разъяснение организаторов, если оно появится, следует приложить к решению с датой и точной формулировкой, а не заменять его общим предположением «облако разрешено».

## Как проверить Mac без потери оставшегося времени

Нативный `mps` — уже предусмотренный путь исполнения проекта. [Документация PyTorch](https://docs.pytorch.org/docs/stable/notes/mps.html) описывает работу на GPU macOS и проверку `torch.backends.mps.is_available()`. Она подтверждает механизм, но не скорость Qwen3-VL на данном Mac и не совместимость каждой операции выбранной версии модели. Конкретная версия macOS и пакетов должна быть проверена фактически.

Для резервного M4-пути контрольный этап — установка зависимостей, подготовка весов, проверка хешей и искусственный model smoke. Команды ниже относятся к Mac и на нём не выполнялись. Основной первый CUDA-прогон на RTX 4050 описан в RTX_4050.md:

```bash
python scripts/check_model.py --model-dir models/Qwen3-VL-2B-Instruct --verify-hashes
python scripts/check_model.py --model-dir models/Qwen3-VL-2B-Instruct --device mps --load
python scripts/check_model.py --model-dir models/Qwen3-VL-2B-Instruct --device mps --smoke
```

Проверка `--load` означает только успешную загрузку весов. `--smoke` использует искусственное изображение и проверяет генерацию; это еще не банковский детектор. Время полного пользовательского запроса нужно измерить отдельно после получения разрешенных данных и включения правил с подтвержденными условиями наблюдения. Сейчас три правила реестра отключены; новый сервер не исправляет это ограничение.

Для первого измерения разумно выделить 30–60 минут на установку и проверку пути исполнения, учитывая фактическую скорость загрузки весов. Это контрольный бюджет команды, не обещание длительности установки. Затем необходимо проверить самый длинный доступный ролик и повторные запросы с теми же настройками. В бюджет кейса входят полный путь запроса и получение результата; остановка процесса за 275 секунд с ошибкой не является успешной обработкой.

Сравнивать варианты следует по измерениям: успешное завершение всех выбранных validation-видео, полное время каждого запроса, максимальная память, стабильность нескольких запусков и качество результатов. Смена Mac на более дорогой GPU может ускорить тот же конвейер; она не доказывает лучшего обнаружения или нормативной обоснованности. При настройке нельзя скрыто выбрасывать окна записи, чтобы пройти лимит времени.

## Как должен выглядеть собственный GPU-вариант

Это проверяемая спецификация варианта, а не описание уже арендованного сервера:

1. Один сервер команды содержит API, worker и локальные веса разрешенной коммерческой модели. Внешняя обработка изображений, OCR, LLM и распознавание не подключаются.
2. Интернет нужен на этапе загрузки зависимостей, контейнеров и публичных весов. Затем анализатор запускается без исходящего доступа к интернету. Входящие запросы жюри обслуживает gateway.
3. Конфигурация [compose.yaml](../compose.yaml) отделяет `inference` от входящей сети; модель подключена только к `internal`-сети. [Официальная документация Docker](https://docs.docker.com/reference/compose-file/networks/#internal) описывает `internal: true` как создание сети без внешней связности. На фактическом сервере это нужно проверить исполнением, а не только чтением YAML.
4. Конкретные регион хранения, права доступа, журналы, snapshots, резервные копии и удаление должны быть известны для выбранной услуги. Ни «облако», ни «GPU VM» не означают автоматически Казахстан, отсутствие администраторского доступа или отсутствие копий.
5. Снаружи открыт только необходимый вход к сервису; API-ключ не попадает в URL, логи и репозиторий. При передаче через внешний адрес проверяется защита канала и отсутствие посторонней обработки содержимого.
6. Выполняется проверка реального внешнего `POST → polling → done`, JPEG и таймкодов. Работа модели при заблокированном исходящем интернете фиксируется отдельно от доступности публичной страницы.

Провайдер, бюджет и GPU в этой работе не выбраны. Поэтому не приведены неподтвержденные цены, обещания наличия GPU, конкретный регион или гарантии обращения с данными. Документация отдельного провайдера потребуется для проверки уже выбранного варианта; она не может сама разрешить конкурсный кейс. Аренда, создание учетных записей и передача кому-либо видео не выполнялись.

## Публичный URL для Mac и для GPU

Требование URL существует при обоих вариантах. Запуск на `127.0.0.1` обеспечивает только локальную проверку. Для Mac еще неизвестно, позволяет ли сеть принимать внешние запросы, доступен ли управляемый командой адрес и сможет ли устройство непрерывно работать до конца проверки жюри. Для VM нужно отдельно проверить входящий порт, gateway и адрес.

Туннель или обратный прокси — транспортный компонент, а не автоматически AI-сервис. Однако посредник может видеть содержимое, если завершает TLS, или сохранять журналы. Нельзя объявлять любой публичный туннель допустимым только на основании того, что модель остается на Mac. Конкретный способ внешнего доступа здесь не выбран. Он должен сохранять исходное ограничение на передачу тестовых данных третьим лицам и не добавлять облачный анализ.
