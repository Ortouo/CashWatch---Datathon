## Воспроизведённый дефект и принятый код

После успешного чтения синтетического VP9 длительностью 3 секунды тест заменил доступные media metadata на неизвестную длительность. До изменения экспорт сохранял `source.duration_sec: 3`, хотя ожидался `null`: **дефект воспроизведён в нашей среде**. В отчёте Plus 2 соответствующий искусственный fixture имел длительность 3,143067 секунды; это отдельная величина тестового файла, не время инференса.

Принято исправление `updateManualTime()`: длительность сбрасывается в `null`, если metadata недоступны или media сообщает об ошибке. Одновременно обновляются подпись файла и доступность перехода/добавления отметки. Уже внесённые человеком отметки и заметки сохраняются. Сообщение экспорта больше не утверждает, что отметок нет: при неизвестной длительности сохранённые отметки требуют проверки. Схема JSON и API не менялись.

Новый синтетический regression проверяет три состояния после корректного декодирования: `duration=NaN`, `video.error` и `readyState=0`/`emptied`. Для каждого подтверждены `duration_sec=null`, сохранение прежней отметки 1,25 с и заметки, недоступность новых отметок/seek, скрытие устаревшей длительности и восстановление после возврата действительных metadata. Остальные сценарии сохраняют проверки SHA, aliases, late digest, ошибок SHA, текстовой безопасности, вариантов readiness, HTTP 401 и памяти ключа.

Окончательный прогон: **20/20, 7,32 с** — это длительность браузерного теста, не анализа видео. `node --check` для приложения и теста, а также `git diff --check` выполнены отдельно. При выборе/редактировании/экспорте журнала HTTP-запросов нет; в наборе нет отправок файлов во внешние сервисы и исключений JavaScript. `localStorage` и `sessionStorage` пусты.

Эти результаты не заменяют проверку проигрывания в браузере, полного MOV/API-пути, качества или внешнего сервиса.

## Оставшиеся действия на целевой версии

1. Сохранить имеющийся локальный журнал до обновления страницы. Подтвердить вход с правильным ключом, не передавая ключ в чат.
2. На Mac воспроизвести только искусственный проверочный ролик, добавить отметку, скачать JSON и открыть его локально; сверить SHA, `kind`, `is_ground_truth`, длительность и отсутствие лишних данных.
3. После подтверждённой готовности модели и допуска правил проверить настоящий сквозной запрос, его полное HTTP-время и доступ с другой сети. До этого успешные UI-тесты не обозначают готовность к сдаче.

Команда повторения находится в конце исторического раздела журнала ниже; актуальный сценарий — `tests/frontend_manual_review.cjs`. Из полученного ZIP тестовые команды не исполнялись. Снимки временной QA и исходные материалы не являются обязательной частью пакета.

## Ограничения результатов

Этот Chromium Headless не содержит H.264-декодера: `canPlayType` для H.264 вернул пустую строку, а MOV — `DEMUXER_ERROR_NO_SUPPORTED_STREAMS`. Для H.264 проверен корректный путь предупреждения. Реальное чтение видео и переход к моменту проверены на MP4/VP9, который этот браузер поддерживает. Это ограничение выбранной сборки браузера; оно не является измерением возможностей серверного FFmpeg или всех пользовательских браузеров.

Не проверялись Safari, физические мобильные устройства, реальные конкурсные видео, загрузка локальных весов и сквозной анализ моделью. Пять минут непрерывного ожидания в реальном времени, длительная нагрузка и отказ удалённой сети жюри также не проверялись в рамках этого UI-прогона. Серверные тесты и итоговая готовность релиза фиксируются отдельно интегратором.

Скриншоты использовались для визуальной QA и не входят в поставку. Тестовые ролики, JPEG, перехваченные ответы, ключ и временные инструменты также не включаются в архив проекта. Для чтения этого отчёта или запуска приложения они не требуются.

**Вывод по интерфейсу:** обнаруженных блокирующих UI-дефектов в проверенном контракте нет; frontend готов к заморозке. Готовность всего решения к конкурсу зависит от локальной модели, подтверждённых правил, данных и сквозной проверки — эти условия данный отчёт не подтверждает.

## Дополнение: локальный журнал ручного просмотра

17 октября 2026 добавлен компактный раскрывающийся журнал под выбранным видео. Он доступен до готовности модели и до ввода API-ключа. Отдельный точечный прогон новых рисков завершился **10 из 10 успешных проверок**; прежняя матрица из 25 сценариев целиком не повторялась.

### Что сохраняет журнал

Файл `cashwatch_manual_review_v1-<короткий SHA>.json` содержит `schema_version: 1`, `kind: "cashwatch_manual_review"`, `is_ground_truth: false`, источник (`filename`, полный SHA-256, `size_bytes`, `duration_sec`), свободные `group_id`/`camera_id`, массивы `rule_reviews` и `marks`, общую `note`. Каждый элемент проверки правила содержит `rule_id`, `applicability` и заметку. Допустимые состояния применимости — `unknown` по умолчанию, `confirmed`, `not_applicable`. Отметки содержат исходный `timestamp_sec` и заметку.

Это ручной журнал для последующего review. Он не является predictions или готовой эталонной разметкой; бинарного verdict, назначения split и включения правил в нём нет. Group ID сам по себе не доказывает независимость сцен. ID правила вводится человеком из проверяемого реестра; интерфейс не придумывает нормативные классы.

SHA-256 вычисляется Web Crypto непосредственно из локального файла. До окончания хеширования или при ошибке редактирование журнала и экспорт недоступны; просмотр остаётся доступен. Если браузер не прочитал длительность, она экспортируется как `null`, а добавление новых временных отметок недоступно. Ранее внесённые ручные отметки сохраняются и требуют проверки. Это ограничение просмотра не выдаётся за вывод модели.

Записи восстанавливаются в памяти страницы по полному SHA, в том числе при выборе того же содержимого под другим именем. Экспорт указывает имя текущего выбранного файла. Выбор, правки и экспорт не отправляют содержимое на сервер. Данные не сохраняются в `localStorage`/`sessionStorage`; перед закрытием необходимо явно скачать JSON. При несохранённых изменениях запрашивается стандартное предупреждение браузера о закрытии страницы; мобильный браузер не обязан показывать его при завершении приложения. Без скачивания журнал не переживает перезапуск страницы. В экспорт автоматически не включаются API-ключ, кадры, URL сервера или абсолютные пути; имя файла и введённые человеком заметки остаются чувствительными локальными данными.

### Фактически выполненные проверки

Среда: прежние Playwright 1.52.0 и Chromium Headless 136.0.7103.25 на Linux. Использовались реальные HTML/CSS/JS проекта, настоящий Web Crypto и локальный статический тестовый сервер. `/healthz` и `/capabilities` отвечали **синтетическими заготовками** с отсутствующей моделью; это не повторный smoke реального backend. Реальный MOV/H.264 использовался только как искусственный файл для выбора/хеша, а проигрываемый MP4/VP9 — для чтения длительности 3 секунды и отметки 1,25 секунды. Во всех случаях содержимое было синтетическим.

| Проверка | Результат |
|---|---|
| Журнал и SHA-экспорт до авторизации/модели | Доступны; анализ остаётся заблокированным. SHA совпал с независимо вычисленным Node.js. |
| Длительность, таймкод, JSON и текст заметок | Браузер прочитал синтетический VP9; поля экспорта соответствуют контракту, HTML в заметках не исполняется, ключ отсутствует. |
| Все состояния применимости и незавершённый ввод | Поддержаны три состояния; обновление одного rule_id сохраняет одну запись; незаписанный ввод не теряется молча при экспорте. |
| Переключение исходников | Разные SHA разделяют записи; тот же SHA под новым именем восстанавливает журнал с правильным источником. |
| Удаление и заметка без отметки | Удалённые строки отсутствуют в JSON; экспорт блокируется, пока заметка не привязана к отметке или не перенесена. |

| Общие ошибки | Нет исключений JavaScript, отправок файлов и внешних запросов в этих сценариях. |

Проверены синтаксис `app.js` и тестового сценария через `node --check`. Сценарий сохранён в `tests/frontend_manual_review.cjs`; он не добавляет npm-зависимости приложению и не запускается обычным pytest. Для повторения нужны отдельно установленный Playwright/браузер и **только синтетические** MOV/H.264 и MP4/VP9 длительностью 3 секунды:

```bash
CASHWATCH_PLAYWRIGHT_MODULE=/absolute/path/to/playwright \
CASHWATCH_SYNTHETIC_MOV=/absolute/path/to/synthetic.mov \
CASHWATCH_SYNTHETIC_MP4=/absolute/path/to/synthetic-vp9.mp4 \
node tests/frontend_manual_review.cjs
```

Если браузер установлен в отдельной папке, дополнительно задаётся `PLAYWRIGHT_BROWSERS_PATH`. Снимки и сухой тестовый отчёт создаются во временной папке; они не входят в поставку и не нужны для работы журнала. Ограничения H.264/Safari и отсутствие реальной генерации, указанные выше, сохраняются.
