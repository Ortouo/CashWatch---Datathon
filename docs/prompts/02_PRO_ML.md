## Контекст и цель

Локальная модель определяет событие, тип, исходное время и кадры. Критерии: detection 25, localization 15, classification 15, rules 15, robustness 10, product 10, technical 10. Победу не обещай. Архив разобран локально: **42 MOV + 1 XLSX, 22 positive / 20 normal, 40 уникальных SHA, две пары дублей**; у одной пары различаются таймкоды. Закрытой таксономии нет. Полный официальный текст №231 и история получены и сверены; текущая редакция подтверждена; см. [REGULATIONS.md](../REGULATIONS.md). Все три правила `enabled=false` до проверки применимости на видео. Qwen3VLProcessor/tokenizer проверен на синтетике Linux CPU; веса Qwen не загружены, генерация не проверена. Локальный замороженный DINOv2 (Apache 2.0) и линейный классификатор прошли functional fit: **4 уникальных видео, 326 кадров, 85 окон, 71 в fit, 31,029 с CPU**. Качество не измерялось, в API не включён. Подробности: [FUNCTIONAL_TRAINING.md](../FUNCTIONAL_TRAINING.md), [DINO_FUNCTIONAL_CPU.json](../verification/DINO_FUNCTIONAL_CPU.json).

## Работа по шагам

1. **Первые 15 минут — технический статус.** Проверь версии Windows/WSL, видимую Linux RAM, `nvidia-smi --query-gpu=name,memory.total,memory.free,driver_version --format=csv,noheader`, `torch.cuda.is_available()`, Python и FFmpeg. Следуй `RTX_4050.md`; готовые этапы не переустанавливай. `.wslconfig` автоматически не меняй. Передай фактический статус, даже если дальше обнаружен блокер; при ошибке сообщи точный безопасный code и этап.
2. **Веса и настоящая синтетическая генерация — ближайший handoff.** Прими текущую согласованную версию кода. Скачай только публичный Qwen3-VL-2B-Instruct, если он отсутствует, с `--revision 89644892e4d85e24eaac8bacfd4f463576704203`; проверь manifest/revision/`--verify-hashes`. Верни offline env по runbook, затем выполни `python scripts/check_model.py --model-dir models/Qwen3-VL-2B-Instruct --smoke --device cuda --seconds 120`, сохрани stdout JSON и stderr отдельно в `local_reports`. Здесь используется искусственный JPEG. Параметр `--seconds` ограничивает генерацию после загрузки, а не cold load или всё время процесса. Передай Pro 1 `weights_loaded`, `real_generation_tested`, `device`, `load_seconds` либо установленный технический блокер **до перехода к банковскому видео**. Если нужно проверить FFmpeg/supervisor, используй двухсекундную синтетику из `MAC_M4.md` с `benchmark_local.py --profile rtx-4050 --device cuda --mode analyzer --seconds 275 --repeat 1` и собственным `--out`. Локальный network guard не отключай.
3. **Следом — один полный train/development-замер либо установленный блокер.** После успешного синтетического smoke согласуй с Plus 1 разрешённый development/train-вход: сверь его SHA с приватным источником/очередью, исключи защищённые validation/holdout SHA, алиасы и известные группы по [LOCAL_RULE_REVIEW.md](../LOCAL_RULE_REVIEW.md). Само имя файла или отсутствие известной группы не доказывает независимость. Затем выполни `benchmark_local.py --profile rtx-4050 --device cuda --mode analyzer --seconds 275 --repeat 1` с `--video` и `--out` по runbook. Профиль: 1 fps, окно 6 с / перекрытие 2 с, максимум 8 кадров, 384 px, 768 токенов, один процесс. На этом этапе не запускай параллельно DINO и не включай правила для обхода ошибки 503. Запиши wall/model_load time, stage, peak RAM/VRAM, completed_windows, complete/failed/timeout и ошибки JSON. Analyzer-only не даёт jury verdict. Если возникает OOM, различи RAM при загрузке и VRAM при размещении/генерации; не скрывай проблему CPU fallback. Прохождение синтетики не подтверждает, что полное видео поместится в память или уложится в бюджет.
4. **Реестр и jury reference.** Plus 1 с Pro 1 отдельно допускают применимые правила; юридический текст и текущая редакция уже сверены. После принятия изменений и фиксации кода выполни `--mode jury --rules config/rules.json` с тем же CUDA-профилем и сохрани `local_reports/benchmark-rtx4050-jury.json`. Нужны `contract_stable=true`, полный `runtime_contract`, все runs complete/done и успешный лимит времени. Не заменяй failed ответом no_violation. Затем по RTX runbook подними API одним worker; Pro 1 проверит его через `jury_check.py --expect-benchmark`. Смена кода/модели/правил/параметров требует нового сопоставимого замера и перезапуска.
5. **Честная validation.** Сохрани `training_exposure_ledger.local.json`: четыре обучающих SHA, все пять алиасов и связанные сценарии исключаются из оценки. Спорные таймкоды и независимые группы согласуй с Plus 1. Первый короткий успех дополни длинным входом, положительным/отрицательным случаем и другим ракурсом, если они доступны в назначенном validation. Не используй будущий holdout для этого выбора. API-время включает передачу запроса/ответа; оно измеряется отдельно от benchmark.
6. **Улучшение только после baseline.** Выбери один измеренный тип ошибки: пропуск, ложная тревога, класс, время или неверная применимость. Проверь одну гипотезу на неизменном validation и сохрани вариант для отката. Dense refinement, ROI/pose или новый backend допустимы после такого обоснования; идентификация лиц и потеря покрытия запрещены. Functional DINO checkpoint имеет `threshold=null`, `deployment_ready=false`; не включай candidate pruning или переобучение вслепую. Для него нужны независимые группы, полнота кандидатов, FPR, ошибки по ракурсам и выигрыш времени. Пока этого нет, оставь эксперимент отключённым.

## Неизменяемые требования

API: POST multipart `file` → `{job_id,status:"processing"}`; GET задания → processing/done/failed. Done содержит `job_id,status,verdict,violations`; событие — `type,timecode_sec,description,evidence_frames`, кадр — `timestamp_sec,image_base64`. Два verdict: `violation`/`no_violation`; 1–3 настоящих JPEG на событие. `unsupported`, model missing, incomplete и unknown не превращаются в успешный `no_violation`. Ошибка — `failed` с code/message, дополнительные ограничения идут в `/details`.

Лимит — **5 минут на ролик**, включая загрузку весов внутри запроса. Банковские видео, кадры и описания сцен запрещено передавать облачным GPT/API; анализ только локально, без аудио и face identity. Dataset, test/holdout, разметка, embeddings, веса и ключи никогда не коммить в GitHub. Используй только веса с разрешённым коммерческим применением. В чат передавай код, синтетику и обезличенные агрегаты. Не выдумывай правовые ссылки, метрики и факт обучения.

## Приёмка и передача

Передай воспроизводимые команды, совместимый адаптер и таблицу baseline/кандидат: completion rate, precision/recall/F1, ложные срабатывания, локализация при нескольких допусках, классы/ракурсы, latency и размер каждой выборки. Недоступное измерение обозначь «не измерено». После фиксации параметров проведи отдельный holdout через `scripts/evaluate.py`; одинаковые условия сравнения обязательны.

**Первый handoff Pro 1:** `stage`, версии Python/Torch/CUDA, видимые RAM/VRAM, `weights_verified`, `synthetic_generation_done`, `benchmark_mode`, `status`, `wall_seconds`, `model_load_seconds`, число окон, `latency_budget_passed`, `contract_stable`, `runtime_contract.fingerprint`, один безопасный error code или следующий шаг. Показатели должны быть реально получены; неизвестное — `unknown`. Полный benchmark может содержать SHA банковского входа: в облачный чат передай только перечисленные технические поля, без исходных имён/SHA, кадров, сцен, приватных путей и ключей. Приватные полные отчёты остаются у команды локально.

В финале: **статус; файлы/commit/patch; действительно запущенные команды; измеренные результаты; неизвестное; инструкция интеграции и отката для Pro 1**. Не представляй functional fit как проверенное качество.
