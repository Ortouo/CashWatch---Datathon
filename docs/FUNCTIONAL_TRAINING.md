# Первый фактический локальный обучающий прогон

**17 октября 2026 года завершён реальный четырёхроликовый прогон:** локальный замороженный DINOv2-small вычислил признаки, затем StandardScaler и LogisticRegression обучились на слабых временных метках. Это подтверждает работоспособность извлечения признаков и обучения собственного небольшого классификатора. Независимое качество, соблюдение нормативных правил и скорость основного Qwen-анализатора этот эксперимент не измеряет.

Источник результатов — локальные `report.aggregate.json`, `head.functional.local.json` и неизменяемый `training_exposure_ledger.local.json` одного запуска. Числовой checkpoint и журнал передаются команде отдельно; имена роликов, признаки, кадры и исходное видео не входят в этот документ или публичный исходный код.

## Как ограничено обучение

Скрипт `scripts/functional_smoke.py` читает сначала только manifest. Он группирует записи по SHA, исключает неоднозначные аннотации одинаковых байтов, существующие validation/holdout и уже известные связанные с ними группы, затем выбирает по два источника каждого класса в порядке SHA. Одна группа одинаковых файлов с разными официальными таймкодами исключена до ручной проверки. Различие таймкодов может обозначать несколько событий; ошибкой таблицы оно не объявляется.

Журнал фиксируется **до чтения первого медиафайла**. В extractor передан отдельный manifest ровно из четырёх записей. У четырёх выбранных SHA есть пять исходных записей-алиасов, поэтому для будущего исключения из оценки зарезервированы все пять. Остальные 38 исходных файлов этот extractor не открывал. Называть их независимым holdout нельзя: один из них является побайтовым алиасом выбранного источника, а принадлежность к близким сценариям и временным вариантам пока не проверена.

Положительные метки назначаются только окнам с центром в пределах ±2 секунд от официального timecode. Остальные окна positive-видео исключены из обучения. Отрицательные окна берутся только из явно нормальных видео. Веса уравнивают суммарный вклад каждого видео внутри класса и затем вклад двух классов. DINO остаётся замороженным; обучаются только scaler и линейный классификатор. Исходные группы, камеры, splits и разметка в общем manifest не меняются.

Небольшое число положительных окон и отсутствие независимых групп делают подбор рабочего порога и оценку качества необоснованными. Поэтому checkpoint имеет отдельный тип `functional_only_frozen_dinov2_temporal_logistic_v1`, не включён в основной анализатор и всегда содержит `threshold=null`, `deployment_ready=false`, `calibration_performed=false`. Нет обучающей «точности», которую можно перепутать с результатом на новых данных. Строгий `scripts/train_temporal_head.py` по-прежнему требует проверенные независимые train/validation группы и не обходит свои проверки для этого набора.

На Linux до импорта Torch, NumPy и sklearn установлен процессный фильтр libseccomp. Реальная проверка показала `EPERM` при создании IPv4/IPv6-сокетов, рабочий Unix socketpair, `no_new_privs`, TSYNC и отсутствие унаследованных интернет-сокетов. Веса загружались из локальной директории с offline flags и `local_files_only=True`; видео, кадры и описания внешним AI API не передавались. Это узкий запрет обычных сетевых вызовов доверенного ML-кода, а не sandbox для враждебной модели; его границы описаны в [MAC_M4.md](MAC_M4.md).

## Воспроизведение на машине команды

Установите зависимости для вашей платформы по README или [MAC_M4.md](MAC_M4.md). На этапе подготовки с разрешённым интернетом скачиваются только публичные веса:

```bash
python scripts/model_download.py \
  --model dinov2-small \
  --revision ed25f3a31f01632728cabb09d1542f84ab7b0056
```

Пересоздайте общий manifest с собственным абсолютным `metadata.input_dir`; labels CSV должен происходить из официальной таблицы. Перед повтором сохраните полученный журнал первого прогона и используйте те же байты и аннотации. Детерминированный выбор зависит от полного набора SHA и меток: изменение входа может открыть другой поднабор и должно считаться новой обучающей экспозицией.

```bash
python scripts/prepare_dataset.py \
  --input-dir /absolute/path/to/open-content \
  --labels /absolute/path/to/labels.local.csv \
  --out /absolute/path/to/manifest.local.json

python scripts/functional_smoke.py \
  --manifest /absolute/path/to/manifest.local.json \
  --model-dir models/dinov2-small \
  --output-dir local_reports/functional-smoke-reproduction-01 \
  --device cpu \
  --threads 4 \
  --extract-timeout-seconds 900
```

Каталог результата должен быть новым: повторный запуск не перезаписывает журнал и не меняет незаметно выбранные источники. До полного воспроизведения сравните SHA-резервации с исходным журналом; выбранные источники и их сценарии остаются обучающими после любого прогона. На Mac можно отдельно измерить `--device mps`, сохраняя настройки, но такой результат ещё не получен. Linux устанавливает сетевой guard; на macOS этот механизм честно сообщает `os_enforced=false`, и режим без внешней сети обеспечивается окружением запуска отдельно.

Артефакты в частном каталоге:

| Файл | Содержимое |
|---|---|
| `training_exposure_ledger.local.json` | Выбор до чтения медиа, SHA, все алиасы и исключения |
| `manifest.selected.local.json` | Ровно четыре исходные записи, исходные группы и splits |
| `features.local.npz` | Локальные числовые признаки и происхождение; не публикуется |
| `head.functional.local.json` | Числовые scaler/коэффициенты без pickle, порог `null` |
| `report.aggregate.json` | Фактические счётчики, время, память и ограничения без имён сцен |
| `extraction.log.local.txt` | Частная диагностика; не включается в публичный исходный архив |

Семь синтетических тестов `tests/test_functional_smoke.py` прошли отдельно: независимость отбора от порядка manifest, учёт SHA-алиасов, исключение protected SHA/groups, распространение защиты по цепочкам SHA-алиасов и известных групп, запись журнала без открытия отсутствующих медиа, отсутствие влияния неразмеченных positive-окон на fit, отклонение лишних или несогласованных feature sources и отказ при отсутствии полезного окна у одного выбранного видео. Это проверки механизма, отдельные от фактического результата на четырёх источниках.

## Следующий обоснованный этап

Команда локально проверяет смысл таймкодов и объединяет связанные записи в группы сценариев, включая копии и варианты после перекодирования. Из будущей оценки исключаются все выбранные SHA и их сценарии по журналу. Только после этого можно зафиксировать независимые train/validation/holdout, обучить строгий temporal head, подобрать порог на validation и сравнить его с Qwen baseline. Подтверждённые наблюдаемые правила, проверка другого ракурса и измеренный предел пяти минут остаются отдельными необходимыми результатами.
