# Матрица приемки ForteBank Datathon 26

Матрица связывает все семь критериев оценки, обязательный сценарий, API и ограничения кейса с конкретными файлами проекта и незавершенными проверками. Цель команды — закрыть все требования, которым соответствует максимум 100 баллов. **Это не заявление о полученных или гарантированных 100 баллах.** В кейсе нет формулы перевода наших локальных метрик в баллы жюри.

Источник требований — предоставленный организаторами документ «Кейс_ForteBank.docx», SHA-256 `f73a951c87aca9d540076aacc5b4fd8a688810a4ec827b1a382512c770d278a0`. Проверены текст и все семь страниц его рендера: основной сценарий на стр. 1–2, критерии и API на стр. 3–4, FAQ на стр. 5–7. Ссылки вида «§ 10» и «FAQ 17» ниже относятся к этому документу. Матрица составлена 17 октября 2026 года. Позднее в этот же день команда уточнила дедлайн: **18 октября 2026 года, 12:00 Asia/Almaty**; [официальное расписание события](https://datathon.com.kz/schedule) также указывает завершение 18 октября в 12:00 по времени Астаны. Подробности времени и вариантов запуска — в [HOSTING_DECISION.md](HOSTING_DECISION.md).

## Фактическое состояние

- Код API, интерфейса, локального анализатора, правил и инструментов оценки написан. Проверки кода используют синтетические данные, подставные ответы анализатора и искусственные видео. Они не измеряют качество модели на банковских сценах.
- На этапе первичного исследования `open.zip` был недоступен. Теперь архив получен локально: проверены 42 MOV, 42 явные бинарные метки (22/20), 22 таймкода и метаданные. Найдены две пары побайтовых дубликатов и одна неоднозначность временной разметки; исходные записи сохранены. [DATA_AUDIT.md](DATA_AUDIT.md) фиксирует только агрегаты. Семантическая видеопроверка и применимость норм не подтверждены; независимое качество обнаружения, локализации, классификации и другого ракурса не измерено.
- В реестре ровно три правила, и **все три имеют `enabled=false`**. Причина: не подтверждены условия наблюдения и применимость к конкретным видео. Полный официальный текст № 231 и текущая редакция уже сверены через официальный API и историю всех 19 версий; сведения сохранены в [ADILET_PROVENANCE.json](verification/ADILET_PROVENANCE.json). Пока нет активных правил, API блокирует анализ с HTTP 503, а не выдает успешное «нарушение не обнаружено».
- После первичных синтетических проверок выполнен реальный локальный функциональный прогон: замороженный pretrained DINOv2-small загрузил веса и извлек признаки из 4 уникальных видео (2 positive + 2 normal), 326 кадров и 85 окон; scaler и LogisticRegression обучены на 71 окне. Полный измеренный интервал — 31,029 с на CPU. До чтения медиа записан журнал, резервирующий все 5 алиасов выбранных SHA; неоднозначный SHA исключен. Это отдельный эксперимент с `threshold=null`, `deployment_ready=false`, без validation/holdout, метрик качества и подключения к API. Подробности — [FUNCTIONAL_TRAINING.md](FUNCTIONAL_TRAINING.md), [VERIFICATION.md](VERIFICATION.md). Основной Qwen-анализатор с полными весами не запускался.
- Публичного развертывания нет. Рабочий адрес UI, адрес API и ключ не переданы жюри. Конфигурация Docker Compose сама по себе не является развернутым сервисом.
- Целевой репозиторий `datathon` не найден в доступном подключении, его точный URL и remote не установлены. Файлы проекта подготовлены локально; это не подтверждение добавления в запрошенный репозиторий.

**Статусы:** «Реализовано» означает наличие проверяемого кода; «Синтетически проверено» — прохождение указанного искусственного сценария; «Частично» — есть механизм, но не закрыта существенная часть требования; «Ожидает» — нужна фактическая проверка или внешний результат. Ни один из этих статусов не равен баллам жюри.

## Как закрывать оставшиеся проверки

Ранее зафиксированный интеграционный прогон завершился с **95 passed, 38 subtests passed** за **13,98 секунды**, с одним предупреждением устаревания зависимости. В него вошли проверки неопределенных наблюдений, ограничения ASGI-загрузки и 11 регрессий HTTP checker. Это снимок инженерной проверки, не прогон банковского датасета или pretrained-модели. Последующие проверки, браузерный результат и границы подтверждённого исполнения описаны в [VERIFICATION.md](VERIFICATION.md).

Архив и явная разметка теперь доступны локально; их структурная проверка описана в [DATA_AUDIT.md](DATA_AUDIT.md). Локальный DINO-эксперимент уже выполнен и не заменяет основной сервис. Далее нужны работающий комплект основного анализатора на оборудовании команды, локальная проверка человеком наблюдаемости условий каждого правила и соответствия события уже проверенному нормативному тексту. Команда фиксирует независимые группы, камеры и разделы до использования кадров для оценки; отдельно учитываются алиасы дубликатов и неоднозначность временной разметки. Все три правила остаются отключенными, пока условия их применимости не подтверждены.

После включения обоснованных правил следует провести полный локальный API-прогон и сохранить отчет с числом видео/событий, TP/TN/FP/FN, ошибками обработки, временем каждого запроса и реальными типами. Настройки выбираются по train/validation; замороженный holdout и тесты жюри не используются для обучения или подбора. Отдельная оценка другого ракурса необходима для утверждения об устойчивости.

Последняя проверка — тот же путь на собственном развернутом сервисе команды при отключенном исходящем интернете у анализатора: загрузка нового MOV, валидный JSON, реальные JPEG и таймкоды, правильный ключ, работающий UI и успешный результат за 300 секунд. Только после этого адреса и ключ становятся конкретным комплектом для сдачи. Даже закрытие всех инженерных проверок не определяет оценку жюри: качество обнаружения и место среди команд устанавливает финальная проверка организаторов.
