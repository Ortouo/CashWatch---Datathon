## Продолжить локально

Установка FFmpeg и публичных весов не зависит от публикации ветки. На уже работающем Mac используйте начало [MAC_M4.md](MAC_M4.md); повторно создавать окружение не требуется.

Для существующей копии из последнего исходного ZIP подготовлен отдельный patch от её точной базы. Сначала выполните проверку применения, затем само применение; при любой ошибке остановитесь и сохраните сообщение. `.env`, модели, данные и локальные журналы в patch не входят. Не используйте `--reject`, `--force` или `reset --hard` для обхода несовпадающей базы.

Для передачи человеку с рабочим GitHub-доступом существует отдельный patch от `main` на базе `14a9e507455abb446062243518321a692d488bef`. Это другой patch: не подменяйте его patch для распакованного ZIP.

Владелец рабочей Git-копии сначала проверяет состояние и получает изменения:

```bash
git status --short
git fetch origin
git log -1 --oneline origin/main
```

После проверки базы создаётся отдельная интеграционная ветка, применяется соответствующий patch и выполняются проверки. Если `main` ушёл вперёд, новые изменения читаются и согласуются; не заменяйте их старой копией. При восстановлении доступа Pro 1 завершит публикацию и вернёт точную ссылку на commit/PR. До появления подтверждённой ссылки команда не должна выполнять `git switch` на предполагаемую удалённую ветку.

## Проверить доступ приложения

В текущем ответе списка доступных установок нет владельца `munlicode`; запрос репозиториев с этим owner вернул пустой список. Это наблюдения о данном подключении, а не полный список установок владельца.

Владелец проверяет, что намеренно выбранный аккаунт имеет доступ к проекту и что подключённое GitHub App установлено с доступом именно к нему. Для личного аккаунта: **Settings → Applications → Installed GitHub Apps → Configure → Repository access**. При `Only select repositories` добавить `nu-datathon-26`, сохраняя ранее выбранные нужные проекты. Официальная инструкция: [проверка и изменение установленного приложения](https://docs.github.com/en/apps/using-github-apps/reviewing-and-modifying-installed-github-apps). Если текущая интеграция использует OAuth, проверяется соответствующее разрешённое OAuth-приложение; эти механизмы не взаимозаменяемы.

GitHub документирует 404 для существующего ресурса при недостаточной авторизации: [диагностика REST API](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api#404-not-found-for-an-existing-resource). Пароли, PAT, cookies и ключ CashWatch в чат не передаются. Делать проект публичным для восстановления доступа не требуется.

## Совместная работа

- Каждый участник указывает базовый SHA, фактический diff, проверки и неизвестное; изменяет назначенные ему пути.
- Публикация кода и работа конкурсного сервиса подтверждаются отдельно.
- После изменения Python-кода, правил, модели или параметров готовится новый benchmark финальной конфигурации. `jury_check.py --expect-benchmark` сверяет её до отправки видео.
- Данные, журналы, исходный exposure ledger, разметка, веса, `.env` и приватные predictions остаются на разрешённых устройствах. `.gitignore` не удаляет ранее опубликованные материалы из истории Git.
