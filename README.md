# CashWatch

Проверка видео кассовых операций · ForteBank NU Datathon 2026

CashWatch помогает проверяющему находить на видео признаки возможных нарушений кассовых правил. Для найденного события предусмотрены таймкод, 1–3 кадра из исходной записи и нормативное основание. Проверяющий может открыть нужный момент и оценить вывод по самому видео.

Приложение объединяет автоматический анализ и ручной просмотр с заметками. Модель работает на сервере команды с локальными весами; банковские видео не передаются облачным AI API. Окончательное решение остаётся за человеком.

## Возможности

- Просмотр MOV и MP4, переход к нужному времени записи.
- Отправка видео на анализ с отображением загрузки и состояния задания.
- Просмотр результата: тип события, описание, таймкод и кадры-доказательства.
- Ручной журнал: временные отметки, заметки и оценка применимости правил.
- Экспорт ручного журнала в JSON.

Выбор файла открывает его для локального просмотра. Загрузка на сервер начинается только при запуске анализа. Ручной журнал доступен и без настроенной модели.

## Как устроен анализ

1. FFprobe читает параметры видео, FFmpeg извлекает кадры с исходными временными метками.
2. Локальная **Qwen3-VL-2B-Instruct** получает последовательности кадров и включённые правила.
3. Backend проверяет структуру ответа, идентификаторы правил и кадров, временные границы и наличие JPEG-доказательств.
4. Интерфейс показывает события и позволяет вернуться к соответствующему моменту записи.

Нормативные ссылки берутся из реестра `config/rules.json`. Правило должно быть проверено на применимость до включения в анализ: по видео нельзя достоверно определить роли сотрудников или действия за пределами кадра.

В проекте также есть отдельный эксперимент с признаками DINOv2 и обучаемым временным классификатором. В основной API он пока не подключён.

## Запуск

Требуются **Python 3.11+**, **FFmpeg** и **FFprobe** в `PATH`. Рекомендуемая версия Python — 3.12. Команды выполняются из корня репозитория.

### Первичная установка

Linux / macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-core.lock.txt
python -m pip install --no-deps -e .
python scripts/init_env.py
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-core.lock.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe scripts/init_env.py
```

`init_env.py` создаёт локальный `.env` с ключом доступа, не перезаписывая существующий файл. Ключ нужно ввести в интерфейсе. Не добавляйте `.env` в репозиторий.

### Запуск установленной копии

В активированном окружении Linux / macOS:

```bash
python -m uvicorn cashwatch.main:app_factory --factory --host 127.0.0.1 --port 8000 --workers 1
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m uvicorn cashwatch.main:app_factory --factory --host 127.0.0.1 --port 8000 --workers 1
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000).

Без модели и включённых проверенных правил доступны интерфейс, ручной журнал и диагностика. Автоматический анализ в этом случае возвращает `503`. Для полного модельного сервера используйте Linux или WSL2: управление процессом модели в native Windows не поддерживается. Запускайте один Uvicorn worker — очередь заданий локальная.

### Подготовка модели

На этапе подготовки с доступом в интернет:

```bash
python -m pip install -e '.[ml,training]'
python scripts/model_download.py --model qwen3-vl-2b --revision 89644892e4d85e24eaac8bacfd4f463576704203
python scripts/check_model.py --model-dir models/Qwen3-VL-2B-Instruct --verify-hashes
python scripts/check_model.py --model-dir models/Qwen3-VL-2B-Instruct --device auto --load
python scripts/check_model.py --model-dir models/Qwen3-VL-2B-Instruct --device auto --smoke
```

Проверки последовательно сверяют файлы, загружают веса и выполняют генерацию на синтетическом изображении. Перед обработкой банковских данных нужно настроить локальный runtime и ограничить его исходящий сетевой доступ.

## API

Все маршруты `/api/v1/*` требуют заголовок `X-API-Key`.

| Метод и маршрут | Назначение |
|---|---|
| `GET /healthz` | Проверка доступности HTTP-процесса |
| `GET /api/v1/capabilities` | Конфигурация и готовность компонентов |
| `POST /api/v1/analyze` | Загрузка видео, multipart-поле `file` |
| `GET /api/v1/jobs/{job_id}` | Состояние задания и результат |
| `GET /api/v1/jobs/{job_id}/details` | Источники правил, покрытие, предупреждения и время обработки |
| `GET /api/v1/rules` | Реестр правил |
| `GET /api/v1/openapi.json` | Схема API |

После загрузки сервер возвращает `202` с `job_id`. Состояния задания: `processing`, `done`, `failed`. Завершённый анализ содержит `verdict`: `violation` или `no_violation`, а также массив `violations`.

Каждое событие содержит `type`, `timecode_sec`, `description` и `evidence_frames`. Кадр представлен исходной временной меткой и JPEG в Base64. Сбой обработки возвращается как ошибка, без заключения об отсутствии нарушений.

Ограничения по умолчанию:

| Параметр | Значение |
|---|---|
| Форматы | MOV, MP4 |
| Размер файла | До 100 МиБ |
| Продолжительность | До 180 секунд |
| Одновременно выполняемые задания | 1; дополнительные запросы получают `429` |
| Бюджет обработки запроса | 275 секунд, включая загрузку, очередь и запуск модели |

Бюджет обработки — предел ожидания, а не измеренная скорость анализа. Фактическую конфигурацию показывает `/api/v1/capabilities`.

## Ручной журнал и данные

Журнал хранится в памяти вкладки и привязан к содержимому файла по SHA-256. Перед обновлением или закрытием страницы экспортируйте нужные записи. После обновления ключ доступа вводится заново.

Экспорт имеет тип `cashwatch_manual_review` и поле `is_ground_truth=false`. Заметки и ручная оценка применимости правил не отправляются в API анализа, не меняют автоматический результат и не включают серверные правила.

Исходные видео, кадры, частные журналы, ключи и локальные отчёты не должны попадать в публичный репозиторий. Скачанными экспортами пользователь управляет отдельно от серверного хранения.

## Проверки и текущий статус

```bash
python -m pip install -e '.[test,training]'
python -m pytest -q
```

Тесты API используют синтетические исполнители и проверяют техническое поведение приложения. Они не измеряют точность распознавания нарушений.

По материалам проекта на 18 октября 2026 года интерфейс и API интегрированы; ручной просмотр и сохранение журнала проверялись отдельно. Полный прогон финального модельного сервера, независимые метрики качества и внешний доступ в актуальном комплекте приёмки не подтверждены. Предварительные правила остаются отключёнными до проверки применимости.
