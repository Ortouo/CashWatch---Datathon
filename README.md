# CashWatch — ForteBank Datathon 26

Локальное веб-приложение для поиска визуальных признаков возможного нарушения кассовых правил: загрузка видео, фоновый анализ, таймкод, 1–3 исходных JPEG-кадра и ссылка на конкретный пункт нормативного акта. Результат предназначен для проверки человеком.

**Текущее состояние: реализована интеграция и инструменты экспериментов; конкурсная готовность не подтверждена.** Предоставленный архив уже получен: 42 MOV-видео и одна таблица XLSX. Разметка и видео обрабатываются локальным кодом; банковские кадры и описания сцен в облачную модель не передаются. Конкурсные метрики не измерены. Процессор Qwen проверен на синтетических изображениях; его pretrained-веса ещё не загружены. Статус отдельного DINO-эксперимента и реальные проверки зафиксированы в `docs/VERIFICATION.md`. Полный официальный нормативный текст и история редакций получены и сверены; три предварительных правила отключены до проверки применимости к видео. Целевой репозиторий — [munlicode/nu-datathon-26](https://github.com/munlicode/nu-datathon-26); 17 октября код прочитан и клонирован, но последняя повторная проверка доступа снова вернула 404. Работа Plus 1 получена из `main` на коммите `14a9e507455abb446062243518321a692d488bef`; объединение с ручным журналом и runtime contract подготовлено в локальной ветке `work/cashwatch-integration-20261017`, публикация пока не подтверждена. Текущий handoff — [GITHUB_INTEGRATION.md](docs/GITHUB_INTEGRATION.md). Публичный сервер ещё не запущен.

Сервис без весов или включённых проверенных правил возвращает понятную ошибку `503`. Он не подменяет отсутствующую модель фиктивным ответом `no_violation`. Тестовые исполнители существуют только в тестах.

Теперь доступны локальный журнал ручного просмотра и общий контракт конфигурации benchmark/API. Продолжение для четырёх ролей — в [промптах](docs/TEAM_PLAN.md); обновление существующей рабочей папки без переустановки зависимостей — в [UPDATE.md](docs/UPDATE.md).

### Основной анализатор

FFprobe определяет видеопоток, FFmpeg извлекает кадры с реальными временными метками. Локальная `Qwen/Qwen3-VL-2B-Instruct` получает последовательности изображений, идентификаторы кадров и текст включённых правил. Ответ проходит строгую проверку структуры, ID правил и кадров, обязательных условий, временных границ и наличия JPEG. Нормативный текст подставляется из проверяемого реестра, а не придумывается моделью.

Начальная конфигурация — 1 кадр/с, окна 12 секунд, перекрытие 2 секунды. Это экспериментальные параметры. Просмотр выборки кадров по всей временной шкале не равен непрерывному просмотру каждого движения. Правила, требующие непрерывного наблюдения или внешних сведений о процессе, нельзя включать без отдельной проверки.

### Обучаемый компонент

Реализован и фактически выполнен отдельный функциональный эксперимент: замороженный DINOv2-small извлёк 326 кадровых представлений из четырёх выбранных видео, на них обучены scaler и небольшая временная линейная head. Весь запуск занял 31,029 с на Linux CPU; это не время Qwen-инференса или API. Она пока **не подключена** к основному анализатору. Порог не выбирался, качество на validation/holdout не измерялось, полное дообучение VLM не выполнялось. Дальнейшая интеграция требует сравнения с baseline на проверенном разбиении. Команда запуска и границы результата: [FUNCTIONAL_TRAINING.md](docs/FUNCTIONAL_TRAINING.md).

## Быстрый запуск интерфейса и API

Нужны Python 3.11+ и FFmpeg/FFprobe в `PATH`. Рекомендуемое окружение разработки — Python 3.12. Команды выполняются из корня проекта.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-core.lock.txt
python -m pip install --no-deps -e .
python scripts/init_env.py
python -m uvicorn cashwatch.main:app_factory --factory --host 127.0.0.1 --port 8000 --workers 1
```

Открыть `http://127.0.0.1:8000`. Ключ создан в локальном `.env`; введите его в интерфейсе. Скрипт не перезаписывает существующий `.env` и не печатает ключ в журнал. Ключ хранится интерфейсом только в памяти вкладки. Без настроенной модели можно проверить страницу, авторизацию и диагностику конфигурации; обработка роликов ещё недоступна.

В Windows команды активации окружения и установка FFmpeg отличаются. Жёсткое завершение группы процессов реализовано и проверяется для POSIX; для конкурсного сервера используйте Linux. Не запускайте несколько Uvicorn workers с текущей локальной очередью и SQLite: каждый создаст собственный диспетчер заданий.

## Подготовка моделей

На отдельном подготовительном этапе с интернетом загрузите только публичные веса и зависимости:

```bash
python -m pip install -e '.[ml,training]'
python scripts/model_download.py --model qwen3-vl-2b --revision 89644892e4d85e24eaac8bacfd4f463576704203
```

Загрузчик проверяет заявленную Apache-2.0, разрешает ревизию в конкретный commit и сохраняет SHA-256 файлов. Он не получает банковские данные. Используются официальные карточки [Qwen3-VL-2B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct) и [DINOv2-small](https://huggingface.co/facebook/dinov2-small); проверяйте лицензию именно выбранной модели, а не всей фамилии моделей.

После загрузки отключите исходящую сеть инференса и выполните:

```bash
python scripts/check_model.py --model-dir models/Qwen3-VL-2B-Instruct --verify-hashes
python scripts/check_model.py --model-dir models/Qwen3-VL-2B-Instruct --device auto --load
python scripts/check_model.py --model-dir models/Qwen3-VL-2B-Instruct --device auto --smoke
```

Первая проверка читает файлы, вторая действительно загружает веса, третья выполняет генерацию на искусственном изображении. Эти проверки не измеряют качество на банковском видео. Прямые ML-зависимости закреплены в `pyproject.toml`, включая согласованную пару Torch/torchvision. Полный lock с транзитивными зависимостями нужно сохранить после успешного запуска на целевом устройстве: проверка Linux CPU не заменяет проверку MPS или CUDA.

`CASHWATCH_DEVICE=auto` выбирает CUDA, затем MPS, затем CPU. Для проверки команды на Mac M4/16 ГБ задавайте `--device mps` явно: так недоступность Apple GPU станет ошибкой, а не незаметным запуском на CPU. Docker-вариант предназначен прежде всего для Linux, отдельно предусмотрено подключение NVIDIA GPU. Производительность на конкретном Mac/GPU здесь не измерена.

## Данные, правила и первая оценка

Исходный архив уже структурно проверен: 42 MOV, 22 положительные и 20 отрицательных меток, 40 уникальных SHA. Полный агрегированный аудит и неоднозначность таймкодов у одной пары дубликатов описаны в [DATA_AUDIT.md](docs/DATA_AUDIT.md).

Видео, кадры, их описания и разметку держите в разрешённой локальной среде. Кейс запрещает передавать их облачным AI API. Не прикладывайте банковские ролики к четырём GPT-чатам. Для работы над кодом передавайте исходники, интерфейсы и обезличенные агрегаты метрик.

1. Распакуйте архив на локальном компьютере команды. Сохраните исходники неизменными.
2. Подготовьте манифест. Команда не угадывает метки и не выполняет случайное разбиение автоматически.

```bash
python scripts/prepare_dataset.py --input-dir /absolute/path/to/open --out data/manifest.local.json
```

3. Сопоставьте официальную разметку с относительными путями видео. Формат CSV и повторный импорт описаны в [DATA_AND_EVALUATION.md](docs/DATA_AND_EVALUATION.md). Проставьте группы сценариев, камеру и разделы `train`, `validation`, `holdout` до извлечения кадров. Варианты одной постановки и дубли должны оставаться в одной группе.
4. Проверьте правила по [REGULATIONS.md](docs/REGULATIONS.md): полный действующий текст, область применения, исключения, видимые условия. Включайте `enabled=true` только у подтверждённых правил. Отсутствие видимого контролёра, движение руки в карман или незакрытый ящик сами по себе не образуют универсальное нарушение.
5. После успешного `benchmark_local.py --mode jury` выполните базовый прогон на `validation` через настоящий HTTP API. Используйте отчёт именно выбранного устройства и профиля. Режим `--manifest` сохраняет относительные `video_id` и проверяет SHA выбранных файлов. Результат содержит JPEG и описания, поэтому хранится локально.

```bash
python scripts/jury_check.py --base-url http://127.0.0.1:8000 --manifest data/manifest.local.json --split validation --expect-benchmark local_reports/benchmark-rtx4050-jury.json --out local_reports/jury_predictions.json
```

`--expect-benchmark` проверяет успешный, неизменный jury benchmark и совпадение runtime contract **до POST**. Сверяются параметры обработки, заявленная ревизия/хеши модели, реестр правил и исходники Python-пакета; перед следующим видео проверка повторяется. Analyzer-only, неполный или несопоставимый отчёт блокирует загрузку. Обычный smoke без этого флага сохраняет сведения `/capabilities`, но не доказывает совпадение с benchmark. Контракт не проверяет содержимое весов, конкретную GPU или версии PyTorch/CUDA и не измеряет качество. После изменения кода, весов, правил или параметров перезапустите сервис и выполните новый сопоставимый benchmark.

6. Оцените результат:

```bash
python scripts/evaluate.py --manifest data/manifest.local.json --predictions local_reports/jury_predictions.json --split validation --rules config/rules.json --out local_reports/validation_metrics.json
```

Оценщик не выставляет официальный балл жюри. Он считает ошибки по видео, событиям и типам, случаи отсутствующего/ошибочного ответа, локальные диагностические допуски 1/2/5 секунд и доступные показатели задержки. Не настраивайте параметры по `holdout`: используйте его один раз после фиксации модели, правил и prompt.

Обучение временного компонента и ограничения слабой разметки: [ML_ARCHITECTURE.md](docs/ML_ARCHITECTURE.md). Ниже — команды эксперимента после проверки манифеста, а не обещание улучшения:

```bash
python scripts/model_download.py --model dinov2-small
python scripts/extract_features.py --manifest data/manifest.local.json --model-dir models/dinov2-small --output artifacts/dino_features.npz --device auto
python scripts/train_temporal_head.py --manifest data/manifest.local.json --features artifacts/dino_features.npz --output artifacts/temporal_head.json
```

## Контракт для жюри

Все `/api/v1/*` защищены заголовком `X-API-Key`. `/healthz` сообщает только работоспособность HTTP-процесса. `/api/v1/capabilities` проверяет конфигурацию; это не сертификат качества или скорости, и `ready_for_submission` остаётся `false` до отдельной процедуры приёмки.

| Запрос | Назначение |
|---|---|
| `POST /api/v1/analyze` | Multipart, поле `file`; MOV, также поддерживается MP4; ответ `202` с `job_id` и `processing` |
| `GET /api/v1/jobs/{job_id}` | `processing`, `done` или `failed` |
| `GET /api/v1/jobs/{job_id}/details` | Нормативные источники, покрытие, предупреждения, время обработки |
| `GET /api/v1/rules` | Локальный реестр правил |
| `GET /api/v1/openapi.json` | Машиночитаемый контракт API |

Завершённый ответ содержит только согласованные поля:

```json
{
  "job_id": "0123456789abcdef0123456789abcdef",
  "status": "done",
  "verdict": "no_violation",
  "violations": []
}
```

Для `violation` массив непустой. Каждое событие содержит `type`, `timecode_sec`, `description`, `evidence_frames`; каждый кадр — `timestamp_sec` и `image_base64` настоящего JPEG. Нормативное основание включается в `description`, расширенные поля идут в `/details`, чтобы не менять формат жюри. Ошибка задания имеет `status="failed"` и `error`, без verdict.

По умолчанию допускается один запрос в работе. Дополнительный получает `429` и `Retry-After`. Лимит обработки — 275 секунд с начала приёма запроса приложением, включая загрузку, ожидание, холодный старт модели и сериализацию. Supervisor прерывает процесс при превышении срока; это обеспечивает ограничение времени, но не гарантирует успешное завершение длинного видео. Максимальный upload — 100 МиБ; максимальная продолжительность — 180 секунд.

Исходное видео и извлечённые кадры удаляются после задания; необходимые JPEG остаются в защищённом результате. Результаты удаляются по TTL (по умолчанию час). Локальные журналы, экспортированные JSON и резервные копии также требуют удаления в конце работы; сервер не управляет файлами, которые пользователь скачал отдельно.

## Развёртывание и сдача

Сборка контейнеров требует интернета для пакетов; рабочий контейнер модели после подготовки подключён только к внутренней сети Compose. Обратный прокси обеспечивает входящий HTTP. Команды и границы проверки: [DEPLOYMENT.md](docs/DEPLOYMENT.md).

```bash
docker compose up --build -d
```

После запуска страница доступна локально на `http://127.0.0.1:8080`. Это ещё не публичный адрес для жюри. Нужны сервер команды, HTTPS, доступный извне домен/адрес, проверка с другой сети и передача ключа организаторам. Не публикуйте ключ в репозитории.

В этом выпуске Docker-сборка и сетевой запрет контейнера фактически не запускались; отдельный процессный Linux guard проверен настоящими системными вызовами. Перед сдачей необходимо проверить выбранную схему размещения на сервере, провести полный прогон самых длинных видео и убедиться, что сервер доступен в назначенное время.
